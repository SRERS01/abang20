### Complete data types and their potential security vulnerabilities

The table below covers major data types across JavaScript, Python, PHP, Java, C, C++, C#, Go, Rust and SQL, together with the vulnerabilities you should investigate during authorized bug bounty testing.

### 1\. Primitive data types

| Data type  | Potential vulnerabilities to investigate                                          |
| ---------- | --------------------------------------------------------------------------------- |
| Integer    | Integer overflow, underflow, IDOR, business-logic manipulation                    |
| Float      | Precision errors, rounding errors, NaN handling                                   |
| Double     | Floating-point precision, calculation inconsistencies                             |
| Boolean    | Authorization bypass, privilege escalation, fail-open logic                       |
| String     | SQL injection, XSS, command injection, path traversal, authentication logic flaws |
| Character  | Encoding errors, Unicode confusion, truncation                                    |
| Byte       | Buffer overflow, integer conversion errors, binary parsing errors                 |
| Short      | Integer overflow, truncation                                                      |
| Long       | Overflow, underflow, incorrect range conversion                                   |
| Decimal    | Precision loss, rounding manipulation, financial calculation errors               |
| BigInteger | Resource exhaustion, conversion errors, range inconsistencies                     |
| Complex    | Incorrect numerical validation, serialization errors                              |

| Combination              | Vulnerability to investigate  |
| ------------------------ | ----------------------------- |

| String → Object          | Unsafe deserialization        |

| Array → Integer          | Unexpected coercion           |
| Object → Database model  | Mass assignment               |
| Integer → Float          | Precision loss                |
| Float → Decimal          | Rounding inconsistency        |
| Signed → Unsigned        | Sign conversion errors        |
| Null → Boolean           | Fail-open authorization       |
| JSON → Object            | Prototype pollution           |
| Timestamp → Integer      | Expiration and replay errors  |
| UUID → Database query    | IDOR                          |

Important: These are potential vulnerability classes, not proof that a data type is vulnerable. A valid bounty requires demonstrating an actual security impact within the program's scope.

The central principle to remember:

Don't just investigate what type a variable accepts. Investigate what happens when that variable is converted, validated, stored, compared and consumed by another function.
