### High-value bug bounty vulnerabilities: TCPdump + Frida

TCPdump and Frida are a powerful combination for investigating security weaknesses in web applications and Android applications.

However, they work at different levels:

* TCPdump: Observes network communication between devices, applications and servers.

* Frida: Observes application runtime behaviour, including function calls, arguments, return values and execution flow.

The most valuable findings often come from combining network evidence with application-level evidence.

One important distinction: neither tool automatically discovers or proves a vulnerability. They help you trace, investigate and verify it.

### 1\. High-value vulnerability classes to investigate

The following are potentially high-impact bug bounty categories. Actual payouts depend on the program's scope, impact, severity and evidence; there is no guaranteed payout.

Priority research areas

| Vulnerability                      | TCPdump contribution               | Frida contribution                           |
| ---------------------------------- | ---------------------------------- | -------------------------------------------- |
| Authentication bypass              | Observe authentication traffic     | Trace authentication decisions               |
| Authorization bypass               | Observe API communication          | Trace permission checks                      |
| IDOR / BOLA                        | Observe API requests               | Trace object-ID handling                     |
| Payment manipulation               | Observe transaction communication  | Trace amount and transaction processing      |
| Business logic flaws               | Observe request sequences          | Trace business-rule execution                |
| Account takeover                   | Observe authentication flows       | Trace session and token handling             |
| Sensitive data exposure            | Identify unencrypted transmission  | Trace sensitive data handling                |
| Insecure token management          | Observe network transmission       | Trace token storage and usage                |
| Certificate validation weaknesses  | Observe TLS connection behaviour   | Investigate certificate-validation functions |
| Cryptographic implementation flaws | Observe encrypted traffic metadata | Investigate cryptographic function calls     |
| Race conditions                    | Observe request timing             | Trace concurrent execution                   |
| Client-side security bypass        | Observe resulting requests         | Trace client-side security controls          |
| API security weaknesses            | Observe API communication          | Trace API request construction               |
| Payment state inconsistency        | Observe transaction sequences      | Trace application state transitions          |
| Insecure local storage             | Observe data transmission          | Inspect application storage operations       |

### 2\. The highest-priority findings and how to trace them

These are the areas I would prioritize for your research.

### 1\. Payment and financial logic vulnerabilities

High research priority

Examples:

* Incorrect transaction amount validation.

* Payment status manipulation.

* Duplicate transaction processing.

* Incorrect wallet balance updates.

* Payment verification bypass.

* Refund authorization flaws.

* Deposit and withdrawal inconsistencies.

* Currency conversion errors.

TCPdump investigates:

* Transaction request timing.

* Connection sequences.

* Whether retries occur.

* Communication with payment services.

* Whether unexpected network communication occurs.

Frida investigates:

* Amount calculation functions.

* Transaction state transitions.

* Payment validation functions.

* Response-handling functions.

* Local balance-display calculations.

Evidence to establish: A transaction is incorrectly accepted, recorded or credited by the authoritative backend, not merely displayed incorrectly in the application.

### 2\. Authentication and account takeover

Examples:

* Broken authentication.

* Session-management weaknesses.

* Insecure password-reset flows.

* OTP validation weaknesses.

* Token-validation errors.

* Improper session invalidation.

TCPdump: Observe authentication connections, TLS metadata, timing and possible plaintext transmission.

Frida: Trace authentication methods, token handling, session creation and logout functions.

Verification: Demonstrate an unauthorized authentication or session outcome using your own test accounts.

### 3\. Broken authorization (BOLA / IDOR)

Examples:

* Accessing another user's transaction.

* Unauthorized wallet access.

* Unauthorized profile modification.

* Accessing another user's order.

* Unauthorized account operations.

TCPdump: Record API connection timing and request traffic metadata.

Frida: Trace object identifiers, authorization-related client methods and API request construction.

Verification: Use two accounts you control and establish whether one account can access the other's protected test resources.

### 4\. Certificate validation and TLS weaknesses

Examples:

* Improper certificate validation.

* Hostname verification weaknesses.

* Trusting untrusted certificates.

* Insecure communication configuration.

TCPdump: Observe TLS handshakes and connection behaviour.

Frida: Investigate certificate-validation and hostname-verification functions.

Verification: In your own Android test environment, assess whether the application accepts an invalid certificate when it should reject it.

Frida can reveal client-side validation behaviour, but backend TLS security requires separate server-side assessment.

### 5\. Sensitive information exposure

Examples:

* Authentication tokens stored insecurely.

* Personal information exposed in application logs.

* Sensitive information transmitted over plaintext HTTP.

* Credentials exposed through local application storage.

* Excessive API response data.

TCPdump: Investigate network transmission.

Frida: Trace where sensitive values are obtained, processed and stored.

Verification: Establish what sensitive information is exposed, to whom, and under what conditions.

### 6\. Race conditions

Examples:

* Duplicate payments.

* Duplicate withdrawals.

* Repeated coupon redemption.

* Concurrent balance updates.

* Inconsistent transaction states.

TCPdump: Compare network timing and request sequences.

Frida: Trace execution order, shared state and synchronization functions.

Verification: Use a controlled test account and harmless test transactions. Confirm whether the authoritative server creates an inconsistent state.

### 3\. How to combine both tools

Suppose you're testing an Android financial application in an authorized environment.

Android application

Your authorized test account

Frida

Runtime functions, values, execution flow

TCPdump

Packets, IPs, ports, timing

Backend API

Actual authorization and transaction decisions

Evidence correlation

Runtime traces + network captures + backend records

The advantage is that you can compare what the Android application intended to send, what happened on the network, and what the server actually accepted.

### 4\. Frida functions you should master

| Frida capability              | What it helps investigate                           |
| ----------------------------- | --------------------------------------------------- |
| Java.perform()                | Execute instrumentation in the Java runtime         |
| Java.use()                    | Access Java classes                                 |
| Java.choose()                 | Find live Java instances                            |
| Java.enumerateLoadedClasses() | Discover loaded classes                             |
| Interceptor.attach()          | Observe native function calls                       |
| Interceptor.replace()         | Replace functions in an authorized test environment |
| Stalker.follow()              | Trace execution flow                                |
| Memory.scan()                 | Search process memory                               |
| Module.enumerateExports()     | Inspect native library exports                      |
| frida-trace                   | Automatically generate function tracing handlers    |

Frida supports Java and native function instrumentation on Android. OWASP Mobile Application Security +2
