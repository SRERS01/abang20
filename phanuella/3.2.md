## Part A: Network Placement, Zones & Attack Surface Reduction

### 1. Device Placement & 2. Security Zones
* **Concept:** Placing security appliances and servers in strategic network zones to control traffic flow between untrusted and trusted boundaries:
  * **Untrusted Zone (Internet)** $\rightarrow$ **Perimeter Firewall** $\rightarrow$ **Screened Subnet (DMZ)** (hosts public web servers, reverse proxies, mail relays—never internal databases!) $\rightarrow$ **Internal Firewall** $\rightarrow$ **Trusted Intranet / Restricted Database Zone**.
  * **Sensors:** Place **NIDS/IPS** outside the firewall to see raw internet noise and inside the perimeter firewall to see attacks that bypassed edge rules.
* **Practical Task (Map a Multi-Zone Enterprise Architecture with Mermaid):**
  ```markdown
  ```mermaid
  flowchart LR
    Internet((Untrusted Internet)) --> EdgeFW[Edge Firewall]
    EdgeFW --> DMZ[Screened Subnet / DMZ: Reverse Proxy & Public Web]
    DMZ --> IntFW[Internal Segmentation Firewall]
    IntFW --> LAN[Internal User LAN]
    IntFW --> DBZone[(Restricted DB Zone: SQL & Secrets)]
  ```
  ```

### 3. Attack Surface Reduction
* **Concept:** Minimizing the sum of all exposed entry points (open ports, unnecessary services, default accounts, unused software packages, exposed APIs) where an unauthorized user could attempt to enter or extract data.
* **Practical Task (Audit Listening Ports & Remove Unused Services):**
  * **Linux:**
    ```bash
    sudo ss -tulnp
    systemctl list-unit-files --type=service --state=enabled | head -n 15
    ```
  * **Windows (PowerShell):**
    ```powershell
    Get-NetTCPConnection -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess
    ```

### 4. Infrastructure Diversity
* **Concept:** Avoiding monoculture single points of failure by deploying **multi-vendor or heterogeneous controls** across layers (e.g., Palo Alto perimeter firewall + Cisco internal firewall + Linux web servers + Windows Active Directory)—ensuring a single zero-day flaw cannot compromise every tier simultaneously.

## Part B: Zero Trust Architecture & Device Posture

### 5. Zero Trust Architecture (ZTA)
* **Concept:** Architecture based on **"Never trust, always verify"**—removing implicit trust based on physical or IP network location:
  * **Control Plane:** Houses the **Policy Engine (PE)** (evaluates identity, device health, threat intel) and **Policy Administrator (PA)** (generates short-lived session tokens/credentials).
  * **Data Plane:** Houses the **Policy Enforcement Point (PEP)** (proxy/gateway sitting directly between the **Subject** and **Enterprise Resource** that permits or terminates traffic per Control Plane decisions).
* **Practical Task (Simulate Zero Trust Control Plane vs. Data Plane Enforcement in Python):**
  ```python
  def control_plane_policy_engine(subject, device_health, resource_sensitivity):
      if not subject["phishing_resistant_mfa"]:
          return "DENY: FIDO2 MFA required"
      if not device_health["edr_running"] or not device_health["disk_encrypted"]:
          return "DENY: Non-compliant device posture"
      if resource_sensitivity == "Restricted" and subject["role"] != "SecOps_Admin":
          return "DENY: Insufficient RBAC authorization"
      return "ALLOW: Issue 15-minute ephemeral session token to Data Plane PEP"

  print(control_plane_policy_engine(
      {"user": "ambe", "role": "SecOps_Admin", "phishing_resistant_mfa": True},
      {"edr_running": True, "disk_encrypted": True},
      "Restricted"
  ))
  ```

### 6. User Authentication
* **Concept:** Verifying user identity using multi-factor combinations (**Something you know** + **Something you have** + **Something you are**), **Single Sign-On (SSO)** via **SAML 2.0 / OIDC**, and phishing-resistant **FIDO2 / WebAuthn**.

### 7. Device Management, 8. Device Health & 9. Device Inventory
* **Concept:**
  * **Device Management (MDM / UEM):** Enforcing configuration baselines, remote wipe, OS updates, and app restrictions across corporate/BYOD endpoints.
  * **Device Health (Posture Assessment / NAC):** Checking endpoint compliance (AV/EDR active, firewall enabled, OS patched, disk encrypted) *before* granting network or VPN access.
  * **Device Inventory (CMDB / Asset Discovery):** Maintaining an accurate, continuously updated inventory of all hardware/virtual assets ("You cannot protect what you don't know you have").
* **Practical Task (Run a Local Endpoint Health & Posture Check Script):**
  ```bash

  echo "Firewall : $(sudo ufw status 2>/dev/null | head -n 1 || echo 'Check OS Firewall')"
  echo "Disk Enc : $(lsblk -o NAME,FSTYPE | grep -q crypt && echo 'LUKS Enabled' || echo 'Unencrypted Volume')"
  ```

### 10. Application Access Control
* **Concept:** Restricting which binaries/applications are permitted to execute on endpoints (**Application Allow-listing** via Windows Defender Application Control [WDAC] / AppLocker / Linux `fapolicyd`) and controlling OAuth/API permissions granted to cloud apps.

## Part C: Remote Access, Tunneling, Messaging & SSE

### 11. VPN, 12. Remote Access & 13. Tunneling
* **Concept:**
  * **Remote Access:** Securely connecting remote/telework users to internal enterprise resources (via VPN, ZTNA, or Jump Hosts/Bastions).
  * **VPN (Virtual Private Network):** Encrypts traffic across untrusted networks using **IPsec** (Layer 3) or **TLS/SSL / WireGuard** (Layer 4/7). Supports **Full Tunnel** (all traffic routed through corporate VPN for inspection) vs. **Split Tunnel** (only corporate subnet routed via VPN; internet traffic goes direct).
  * **Tunneling:** Encapsulating one network protocol inside another encrypted carrier protocol (e.g., **SSH Local Port Forwarding**, IPsec ESP, GRE over IPsec).
* **Practical Task (Create an Encrypted SSH Local Port Forward Tunnel):**
  ```bash
  # Example syntax: Forward local port 8443 securely through an encrypted SSH tunnel to an internal web app
  # ssh -N -L 127.0.0.1:8443:10.20.2.50:443 user@bastion-host.corp.local
  echo "SSH Local Tunnel Command Verified: ssh -N -L 127.0.0.1:8443:10.20.2.50:443 user@bastion"
  ```

### 14. User Management, 15. User Access & 16. Least Privilege
* **Concept:** Governing the full identity lifecycle (**Provisioning** on hire $\rightarrow$ **Role/Attribute Access** via RBAC/ABAC $\rightarrow$ **Periodic Access Reviews** $\rightarrow$ **Deprovisioning** on termination) while enforcing **Least Privilege** (granting only the minimum permissions needed for a specific role).

### 17. End-to-End Encrypted (E2EE) Messaging
* **Concept:** Cryptographic communication (Signal Protocol, Matrix, S/MIME, PGP) where messages are encrypted on the sender's device and decrypted *only* on the recipient's device—meaning intermediary servers, ISPs, and cloud providers cannot read the plaintext content.

### 18. Out-of-Band Management (OOBM)
* **Concept:** Managing network switches, routers, firewalls, and server hardware (IPMI, iDRAC, iLO, serial console) over a **physically or logically isolated management network** separate from production user traffic—allowing admins to recover devices even if the production network is down or under DDoS attack.

### 19. Secure File Transfer
* **Concept:** Replacing cleartext `FTP` (`port 21`) and `TFTP` (`port 69`) with encrypted alternatives:
  * **SFTP (SSH File Transfer Protocol — `TCP/22`):** Runs over an encrypted SSH channel.
  * **FTPS (FTP Secure — `TCP/990` / `21`):** FTP wrapped in TLS/SSL certificates.
  * **HTTPS / Managed File Transfer (MFT):** Encrypted web/API file exchange with audit logging.
* **Practical Task (Verify SFTP / SCP Availability Instead of Legacy FTP):**
  ```bash
  which sftp scp && echo "[PASS] Encrypted SSH file transfer tools available."
  ```

### 20. Security Service Edge (SSE)
* **Concept:** Cloud-delivered security convergence combining **SWG (Secure Web Gateway)**, **CASB (Cloud Access Security Broker)**, and **ZTNA (Zero Trust Network Access)** into a unified cloud edge service protecting remote users and SaaS traffic without backhauling traffic to an on-premises data center. *(Note: **SSE + SD-WAN = SASE**).*

## Part D: Privileged Accounts & Infrastructure Failure Modes

### 21. Group Managed Service Accounts (gMSA)
* **Concept:** Specialized Active Directory domain accounts designed for automated Windows services/scheduled tasks across multiple servers where Windows **automatically generates, rotates, and manages complex 240-character passwords** every 30 days—eliminating hardcoded service passwords and human password resets.

### 22. Privileged Access Accounts & 23. Privilege Creep
* **Concept:**
  * **Privileged Access Accounts:** High-privilege accounts (`root`, `Domain Admin`, `AWS Root`, `sudoers`) requiring **PAM (Privileged Access Management)**, **Just-in-Time (JIT)** temporary elevation, session recording, and dedicated Privileged Access Workstations (**PAWs**).
### 22. Privileged Access Accounts
* **Concept:** High-impact administrative and service accounts capable of modifying system configurations, accessing sensitive data, or disabling security controls (`root` on Linux, `Administrator` / `Domain Admins` / `Enterprise Admins` on Windows, `AWS Root` / `Global Administrator` in Cloud).
  * *Best-Practice Controls:*
    * **PAM (Privileged Access Management):** Vaulting admin credentials, requiring checkout workflows, and recording privileged sessions.
    * **Just-in-Time (JIT) / Just-Enough-Administration (JEA):** Granting temporary elevated privileges only for a specific maintenance task (e.g., 1 hour) and automatically revoking them afterward.
    * **Privileged Access Workstations (PAWs):** Dedicated, hardened admin machines blocked from web browsing and email to prevent credential theft via phishing.
* **Practical Task (Audit Privileged `sudo` & Root-Level Accounts on Linux / Windows):**
  * **Linux:**
    ```bash
    # List all accounts with UID 0 (root-equivalent)
    awk -F: '($3 == "0") {print $1}' /etc/passwd

    # Check members of privileged sudo / wheel groups
    getent group sudo wheel 2>/dev/null
    ```
  * **Windows (PowerShell):**
    ```powershell
    Get-LocalGroupMember -Group "Administrators" | Select-Object Name, ObjectClass, PrincipalSource
    ```

### 23. Privilege Creep
* **Concept:** The gradual, unauthorized accumulation of excessive access permissions over an employee's tenure as they switch roles, transfer departments, or take on temporary projects without their legacy permissions ever being revoked. Directly violates the **Principle of Least Privilege**.
  * *Primary Mitigations:* **Periodic Access Reviews / Attestations** (managers re-certify team permissions quarterly), **Role-Based Access Control (RBAC)** templates tied to HR job codes, and automated deprovisioning workflows upon role change.
* **Practical Task (Build an Automated HR-to-IAM Privilege Creep Auditor in Python):**
  ```python
  # Compare HR's official role-permission baseline against actual Active Directory / Cloud IAM assignments
  hr_role_matrix = {
      "Junior_Analyst":   {"VPN_Users", "SIEM_Read", "Ticketing_Portal"},
      "Finance_Officer":  {"VPN_Users", "ERP_Billing", "Payroll_Read"},
      "Cloud_Engineer":   {"VPN_Users", "AWS_Dev_Admin", "Git_Repo_Write"}
  }

  active_directory_users = [
      {
          "username": "ambe.fon",
          "current_hr_role": "Junior_Analyst",
          "previous_role": "Finance_Officer",
          "actual_groups": {"VPN_Users", "SIEM_Read", "Ticketing_Portal", "ERP_Billing", "Payroll_Read"}
      },
      {
          "username": "grace.ngwa",
          "current_hr_role": "Cloud_Engineer",
          "previous_role": None,
          "actual_groups": {"VPN_Users", "AWS_Dev_Admin", "Git_Repo_Write"}
      }
  ]

  print("=== QUARTERLY IAM ACCESS REVIEW & PRIVILEGE CREEP AUDIT ===")
  for user in active_directory_users:
      expected = hr_role_matrix[user["current_hr_role"]]
      excess_permissions = user["actual_groups"] - expected
      if excess_permissions:
          print(f"[PRIVILEGE CREEP ALERT] User '{user['username']}' (Role: {user['current_hr_role']}) "
                f"retains unauthorized permissions from '{user['previous_role']}': {excess_permissions}")
      else:
          print(f"[COMPLIANT] User '{user['username']}' strictly matches RBAC baseline.")
  ```

### 24. Infrastructure Failure Modes (Fail-Closed vs. Fail-Open)
* **Concept:** The deterministic default behavior of a security control, firewall, door lock, or network appliance when it experiences a hardware crash, power loss, or software fault:
  * **Fail-Closed (Fail-Secure):** Automatically **blocks all traffic or locks all doors** upon failure. Prioritizes **Confidentiality and Security** over availability (e.g., perimeter firewalls, bank vault doors, authentication servers, VPN concentrators).
  * **Fail-Open (Fail-Safe):** Automatically **permits all traffic or unlocks doors** upon failure. Prioritizes **Physical Human Safety or Business Availability** over security inspection (e.g., emergency fire exit doors in buildings, or inline IDS/IPS appliances in high-availability healthcare/trading networks configured to bypass inspection so traffic isn't dropped).

| Scenario / Infrastructure Component | Recommended Failure Mode | Core Security+ Rationale |
| :--- | :--- | :--- |
| **Perimeter Edge Firewall** | **Fail-Closed (Fail-Secure)** | Prevent uninspected internet traffic from entering the internal network during a crash. |
| **Building Emergency Exit Door** | **Fail-Open (Fail-Safe)** | Human life safety during a fire/power outage overrides physical access restriction. |
| **Data Center Server Cage Door** | **Fail-Closed** (with manual interior panic bar) | Prevents outsiders from walking into server racks during a power outage while letting staff exit safely. |
| **Inline Hospital Network IPS** | **Fail-Open** | Maintaining live patient-monitoring network availability outweighs temporary packet inspection loss. |
| **Authentication / SSO Gateway** | **Fail-Closed** | System errors must never default to granting unauthenticated access. |

* **Practical Task (Simulate Fail-Closed vs. Fail-Open Traffic Enforcement in Python):**
  ```python
  def handle_traffic(appliance_name, state, failure_mode, packet):
      if state == "HEALTHY":
          return f"[{appliance_name}] Inspecting packet '{packet}' normally."
      # Appliance has crashed / lost power:
      if failure_mode == "FAIL_CLOSED":
          return f"[{appliance_name} - CRASHED] FAIL-CLOSED: Dropped packet '{packet}' (Security preserved)."
      elif failure_mode == "FAIL_OPEN":
          return f"[{appliance_name} - CRASHED] FAIL-OPEN: Forwarded packet '{packet}' uninspected (Availability preserved)."

  print(handle_traffic("Edge-Firewall-01", "CRASHED", "FAIL_CLOSED", "TCP/443 Inbound"))
  print(handle_traffic("Hospital-Core-IPS", "CRASHED", "FAIL_OPEN",   "HL7 Patient Vitals"))
  ```
