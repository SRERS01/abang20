## Part A: Data Types & Data States

### 1. Structured Data vs. 2. Unstructured Data
* **Concept:**
  * **Structured Data:** Organized into predefined schemas, rows, and columns (SQL relational databases, CSV exports, spreadsheets)—easy to query and protect with column-level encryption or dynamic masking.
  * **Unstructured Data:** Free-form content lacking a rigid relational schema (PDFs, Word docs, emails, images, audio/video, raw log files)—harder to discover and classify, requiring **DLP (Data Loss Prevention)** regex/ML content inspection.
* **Practical Task (Classify & Scan Both Structured CSV and Unstructured Text for Sensitive PII):**
  ```python
  import re

  structured_row = {"emp_id": 102, "name": "Ambe Fon", "ssn": "123-45-6789"}
  unstructured_memo = "Confidential note: Please verify employee SSN 123-45-6789 before payroll runs."

  ssn_regex = r"\b\d{3}-\d{2}-\d{4}\b"
  print("Structured PII Match  :", bool(re.search(ssn_regex, structured_row["ssn"])))
  print("Unstructured PII Match:", bool(re.search(ssn_regex, unstructured_memo)))
  ```

### 3. Data at Rest, 4. Data in Transit & 5. Data in Use
* **Concept:**
  * **Data at Rest:** Stored persistently on hard drives, SSDs, databases, USB drives, or cloud buckets. *Protected by:* **Full-Disk Encryption (BitLocker/LUKS)**, **AES-256 file/volume encryption**, **TDE**, and **ACLs**.
  * **Data in Transit (Data in Motion):** Actively moving across a network (LAN, Wi-Fi, Internet). *Protected by:* **TLS 1.2/1.3 (HTTPS)**, **IPsec / WireGuard VPN**, **SSH/SFTP**.
  * **Data in Use:** Actively loaded in **CPU registers, RAM, or CPU caches** while being processed/decrypted by an application. *Protected by:* **Confidential Computing / Hardware Enclaves (Intel SGX, AMD SEV)**, **Homomorphic Encryption**, memory isolation, and ASLR/DEP.
* **Practical Task (Protect Data at Rest with AES-256 and Verify Data in Transit with TLS 1.3):**
  ```bash
  # Data at Rest: Encrypt a sensitive file with AES-256
  echo "Customer_Account_Ledger" > accounts.txt
  openssl enc -aes-256-cbc -pbkdf2 -salt -in accounts.txt -out accounts.enc -pass pass:VaultKey2026!

  # Data in Transit: Verify TLS 1.3 transport encryption on an external endpoint
  openssl s_client -connect cloudflare.com:443 -tls1_3 </dev/null 2>/dev/null | grep -E "Protocol|Cipher"
  ```

## Part B: Data Classifications (7 Tiers)

Organizations categorize data by sensitivity and the impact of unauthorized disclosure:

| Classification Tier | Typical Context (Commercial vs. Government/Military) | Security Controls Required |
| :--- | :--- | :--- |
| **1. Public** | Approved for open public release (marketing brochures, press releases, public web pages). | Integrity checks (prevent website defacement). |
| **2. Sensitive** | General umbrella term for any data requiring protection against unauthorized access (PII, internal memos). | Access control, encryption in transit, DLP monitoring. |
| **3. Internal** | Corporate operational data not meant for outsiders, though low harm if leaked (org charts, internal SOPs). | Authentication required, internal-only sharing policies. |
| **4. Confidential** | Proprietary business data whose leak causes competitive or financial harm (pricing models, customer lists, source code). | Strong encryption at rest/transit, RBAC, NDA, DLP blocking. |
| **5. Critical** | Mission-essential data/systems whose loss halts core business operations (production ERP databases, authentication keys). | High availability, immutable backups, strict change control. |
| **6. Restricted** | Highest commercial tier; tightly regulated data where leaks trigger severe legal fines or safety harm (HIPAA PHI, PCI cardholder data, trade secrets). | MFA + PAM, column-level encryption, tokenization, audit logging. |
| **7. Secret / Top Secret** | Government/Military classification tiers where unauthorized disclosure causes **serious** (Secret) or **exceptionally grave** (Top Secret) damage to national security. | Security clearances, air-gapped networks, Type-1 hardware encryption, TEMPEST shielding. |

## Part C: Data Protection Methods (8 Techniques)

* **Practical Task (All-in-One Python Lab Demonstrating All 8 Data Protection Methods):**
  Run this script to see each mechanism in action side-by-side:
  ```python
  import hashlib, secrets, base64

  raw_card = "4532-0151-1283-0366"
  raw_name = "Ambe Fon"

  # 1. Data Masking: Hides sensitive characters while preserving format for support staff
  masked_card = "XXXX-XXXX-XXXX-" + raw_card[-4:]

  # 2. Hashing: One-way fixed-length cryptographic digest (irreversible)
  hashed_card = hashlib.sha256(raw_card.encode()).hexdigest()

  # 3. Filtering: Blocking/stripping sensitive records or fields based on DLP rules
  filtered_export = "[BLOCKED_BY_DLP_POLICY]" if raw_card.startswith("4532") else raw_card

  # 4. Tokenization: Replacing sensitive data with a random, non-mathematical lookup token (PCI-DSS)
  token_vault = {}
  token = "TOK_" + secrets.token_hex(8)
  token_vault[token] = raw_card

  # 5. Encryption: Reversible transformation using a cryptographic secret key
  key = 0x42
  encrypted_bytes = bytes(b ^ key for b in raw_card.encode())

  # 6. Data Transposition: Reordering/scrambling character or column positions
  transposed_card = raw_card[::-1]

  # 7. De-identification (Anonymization/Pseudonymization): Stripping direct identifiers for analytics
  deidentified_record = {"subject_id": "SUBJ-8841", "region": "Southwest", "tx_amount": 250.00}

  # 8. Obfuscation: Encoding/disguising data without a secret key to deter casual inspection
  obfuscated_card = base64.b64encode(raw_card.encode()).decode()

  print(f"1. Masking         : {masked_card}")
  print(f"2. Hashing         : {hashed_card[:32]}...")
  print(f"3. Filtering       : {filtered_export}")
  print(f"4. Tokenization    : {token} (Maps back in vault: {token_vault[token][-4:]})")
  print(f"5. Encryption      : {encrypted_bytes.hex()}")
  print(f"6. Transposition   : {transposed_card}")
  print(f"7. De-identification: {deidentified_record}")
  print(f"8. Obfuscation     : {obfuscated_card}")
  ```

## Part D: Data Protection Responsibilities (6 Governance & Privacy Roles)

| Role | Core Accountability (Enterprise & GDPR/Privacy Frameworks) |
| :--- | :--- |
| **1. Data Owner** | Senior business executive accountable for classifying data, defining retention/access policies, and approving access requests. |
| **2. Data Custodian** | Technical administrator (sysadmin, DBA, cloud engineer) who implements technical controls (backups, encryption, permissions) defined by the Data Owner. |
| **3. Data Steward** | Subject-matter specialist ensuring data quality, accuracy, metadata consistency, labeling, and adherence to governance standards. |
| **4. Data Operator** | Day-to-day personnel/systems entering, updating, or handling operational data in accordance with established SOPs. |
| **5. Data Controller** | Legal entity/organization (under GDPR/privacy laws) that determines **why** and **how** personal data is collected and processed (bears primary legal compliance duty). |
| **6. Data Subprocessor** | Third-party vendor (e.g., cloud hosting provider, payroll processor, email API) contracted by a Data Processor/Controller to process personal data on its behalf. |

## Part E: Data Handling (6 Operational Controls)

### 1. Endpoint Security
* **Concept:** Protecting laptops, desktops, and mobile devices where data is accessed—using **EDR**, **Full-Disk Encryption**, **USB Device Control** (blocking unauthorized removable media), and **Endpoint DLP**.

### 2. Data Marking vs. 3. Data Labelling
* **Concept:**
  * **Data Marking:** Human-readable visual indicators placed on documents, headers/footers, watermarks, or physical media (e.g., `"CONFIDENTIAL — DO NOT DISTRIBUTE"`).
  * **Data Labelling:** Machine-readable metadata tags embedded in file properties or cloud objects (e.g., Microsoft Purview sensitivity labels, AWS S3 object tags `Classification=Restricted`) that allow automated DLP, email gateways, and CASBs to enforce encryption or block external sharing.
* **Practical Task (Attach & Verify Machine-Readable Metadata Tags on a File):**
  ```bash
  echo "Q4 Acquisition Strategy" > merger_plan.txt
  # Attach extended filesystem attributes (xattr) on Linux as a machine-readable label
  setfattr -n user.classification -v "RESTRICTED" merger_plan.txt 2>/dev/null || echo "Label: Classification=RESTRICTED"
  getfattr -d merger_plan.txt 2>/dev/null || true
  ```

### 4. Geofencing, 5. Data Location & 6. Data Placement
* **Concept:**
  * **Geofencing:** Using GPS, IP geolocation, or Wi-Fi/cellular boundaries to restrict where mobile devices or user logins can access corporate data (e.g., blocking logins outside approved countries).
  * **Data Location:** The physical geographic jurisdiction (country/state/data center region) where data resides, governed by **Data Sovereignty** laws.
  * **Data Placement:** Strategically assigning data to specific storage tiers or cloud regions based on sensitivity, latency, compliance, and cost (e.g., placing Restricted PII on encrypted on-premises SANs while placing Public web assets on a global CDN).
### 4. Geofencing, 5. Data Location & 6. Data Placement
* **Concept:**
  * **Geofencing:** Creating virtual geographic perimeters using GPS, IP geolocation, Wi-Fi triangulation, or cellular towers to enforce conditional access—blocking logins, disabling mobile app features, or triggering remote wipes when a device leaves an authorized zone or country.
  * **Data Location:** The physical country, state, or cloud availability zone where data is stored and processed. Directly governs which national privacy laws and government access rules (**Data Sovereignty**) apply to the data.
  * **Data Placement:** Deliberately assigning datasets to specific storage tiers, geographic regions, or on-premises vs. cloud platforms based on **sensitivity classification**, **regulatory compliance**, **latency**, and **cost** (e.g., keeping Restricted citizen/financial records in an approved local or regional data center while placing Public static web assets on a global CDN).
* **Practical Task (Simulate a Conditional Access Geofencing & Data Placement Policy Engine in Python):**
  ```python
  approved_login_countries = {"CM", "NG", "GH", "GB"}
  approved_storage_regions = {"af-south-1", "eu-west-1"}

  access_request = {"user": "ambe.fon", "login_country": "RU", "target_db": "Customer_KYC"}
  storage_plan   = {"dataset": "Customer_KYC", "classification": "Restricted", "target_region": "us-east-1"}

  # 1. Enforce Geofencing on User Authentication
  if access_request["login_country"] not in approved_login_countries:
      print(f"[GEOFENCE DENY] Blocked login for '{access_request['user']}' from unauthorized country: {access_request['login_country']}")

  # 2. Enforce Data Placement & Data Location Sovereignty Rules
  if storage_plan["classification"] == "Restricted" and storage_plan["target_region"] not in approved_storage_regions:
      print(f"[DATA PLACEMENT VIOLATION] Restricted dataset '{storage_plan['dataset']}' cannot be placed in '{storage_plan['target_region']}'.")
  ```

## Part F: Data Lifecycle (5 Stages)

Every piece of organizational data follows a governed lifecycle from birth to secure destruction:

| Lifecycle Stage | Core Governance & Technical Security Controls |
| :--- | :--- |
| **1. Creation** | Immediately assign a **Data Classification Label** (Public, Internal, Confidential, Restricted), assign a **Data Owner**, and apply default encryption/DLP tags at ingestion. |
| **2. Management** | Store securely (**Data at Rest** AES-256 encryption), enforce **Least Privilege (RBAC/ABAC)**, maintain immutable backups, and monitor access via SIEM/DLP audit logs. |
| **3. Distribution** | Protect **Data in Transit** (TLS 1.3, SFTP, E2EE), apply visual **Data Markings** (watermarks/headers), enforce DRM/expiration links, and block unauthorized external sharing via DLP. |
| **4. Retention** | Retain records strictly for the legally or operationally mandated timeframe (e.g., 7 years for financial/tax audits, **Litigation Hold** during legal disputes)—purging expired data early to minimize breach liability. |
| **5. Disposal** | Sanitize or destroy retired media and cloud volumes so data is permanently unrecoverable (must match media type—HDD vs. SSD vs. Cloud). |

* **Practical Task (Test Secure File Sanitization / Disposal Methods via CLI):**
  * **Cryptographic Erasure (Crypto-Shredding — Best for SSDs & Cloud Volumes):** Destroy the AES key protecting the encrypted file so the ciphertext becomes permanently unrecoverable:
    ```bash
    echo "Sensitive_Payroll_Archive" > archive.txt
    openssl rand -hex 32 > archive.key
    openssl enc -aes-256-cbc -pbkdf2 -in archive.txt -out archive.enc -pass file:archive.key

    # Securely delete plaintext and crypto-shred the decryption key
    rm -f archive.txt archive.key
    echo "[DISPOSED] Plaintext & encryption key destroyed; archive.enc is permanently unrecoverable."
    ```
  * **Media Sanitization Rules (Exam Must-Know):**
    * **Overwriting (`shred` / zero-fill):** Effective on magnetic spinning **HDDs**, *unreliable* on SSDs due to wear-leveling controllers.
    * **Degaussing:** Uses a high-powered magnetic field to erase magnetic **HDDs and backup tapes** *(completely ineffective on SSDs/flash media)*.
    * **Physical Destruction:** Shredding, pulverizing, crushing, or incinerating drives when highest assurance is required.

## Part G: Data Compliance (7 Regulatory & Legal Domains)

| Data Compliance Domain | Examples of Protected Data | Key Frameworks, Laws & Technical Mandates |
| :--- | :--- | :--- |
| **1. Health Information** | Medical diagnoses, lab results, prescriptions, health insurance IDs (**PHI**). | **HIPAA** (US) & national health privacy statutes → Requires strict access audits, encryption, and Business Associate Agreements (BAAs). |
| **2. Personal Information** | Full names, National ID numbers, biometrics, home addresses, IP addresses, emails (**PII**). | **GDPR** (EU), **CCPA/CPRA** (California), and national data protection laws → Requires lawful consent, data minimization, right to erasure, and breach notification. |
| **3. Financial Information** | Credit/debit card numbers (**PAN**), CVV codes, bank account numbers, corporate financial statements. | **PCI-DSS** (Payment Card Industry Data Security Standard — mandates tokenization/encryption of PANs, never storing CVV post-auth), **GLBA**, **SOX**. |
| **4. Children's Data** | Personal information collected online from minors (under age 13/16). | **COPPA** (US) & **GDPR Article 8** → Mandates verifiable parental consent, strict retention limits, and bans behavioral ad profiling of minors. |
| **5. Intellectual Property (IP)** | Proprietary source code, R&D blueprints, trade secrets, patents, pharmaceutical formulas. | Protected via **NDAs**, **Digital Rights Management (DRM)**, watermarking, code-repository access controls, and endpoint DLP. |
| **6. Legal Data** | **Litigation Hold** records, e-discovery archives, contracts, attorney-client privileged files, digital forensic chain-of-custody logs. | Litigation holds **suspend normal data disposal/retention deletion** automatically until legal proceedings conclude. |
| **7. Data Protection Standards** | Enterprise-wide information security & privacy management benchmarks. | **ISO/IEC 27001** (ISMS), **ISO/IEC 27701** (Privacy Information Management), **NIST SP 800-53**, **NIST Privacy Framework**, **SOC 2 Type II**. |

* **Practical Task (Build an Automated Data Compliance & Litigation Hold Evaluator in Python):**
  ```python
  records = [
      {"id": "REC-01", "type": "Payment_Card_PAN", "age_years": 2, "litigation_hold": False, "standard": "PCI-DSS"},
      {"id": "REC-02", "type": "Employee_Tax_File","age_years": 8, "litigation_hold": True,  "standard": "SOX / Legal"},
      {"id": "REC-03", "type": "Patient_Lab_Chart","age_years": 9, "litigation_hold": False, "standard": "HIPAA"}
  ]

  max_retention_years = 7

  for r in records:
      if r["litigation_hold"]:
          action = "PRESERVE (Litigation Hold overrides disposal schedule!)"
      elif r["age_years"] > max_retention_years:
          action = f"DISPOSE / CRYPTO-SHRED (Exceeded {max_retention_years}y retention under {r['standard']})"
      else:
          action = f"RETAIN & ENCRYPT ({r['standard']} compliant)"
      print(f"{r['id']} | {r['type']:<18} | Age: {r['age_years']}y -> {action}")
  ```
