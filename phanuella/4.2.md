## Part A: Planning, Scoping & Secure Acquisition

### 1. Asset Planning & 2. Asset Scoping
* **Concept:**
  * **Asset Planning:** Forecasting hardware, software, cloud, and licensing needs aligned with business growth, End-of-Life (EOL) replacement schedules, and security budgets so aging systems do not linger unpatched.
  * **Asset Scoping:** Defining clear boundaries for what assets fall inside an audit, vulnerability scan, compliance scope (e.g., **PCI-DSS Cardholder Data Environment**), or incident response plan—separating regulated production systems from isolated test/guest networks.
* **Practical Task (Build a Scoped Asset Inventory & EOL Forecast in Python):**
  ```python
  from datetime import datetime

  assets = [
      {"asset_id": "SRV-01", "type": "Hardware", "zone": "PCI_Scope", "eol_date": "2026-06-30"},
      {"asset_id": "SRV-02", "type": "Hardware", "zone": "Internal",  "eol_date": "2029-12-31"},
      {"asset_id": "LAB-09", "type": "VM",       "zone": "Out_Of_Scope", "eol_date": "2028-01-15"}
  ]

  today = datetime.now().strftime("%Y-%m-%d")
  for a in assets:
      if a["zone"] != "Out_Of_Scope" and a["eol_date"] < today:
          print(f"[PLANNING ALERT] In-scope asset '{a['asset_id']}' ({a['zone']}) is past End-of-Life ({a['eol_date']})!")
  ```

### 3. Hardware Acquisition & 4. Software Procurement
* **Concept:** Integrating security vetting *before* purchasing or deploying new technology:
  * **Hardware Acquisition:** Sourcing strictly from authorized OEMs/resellers to prevent counterfeit chips or hardware implants, verifying tamper-evident seals, checking TPM 2.0 / Secure Boot support, and evaluating vendor supply-chain security.
  * **Software Procurement:** Conducting vendor security questionnaires, reviewing SOC 2 / ISO 27001 reports, inspecting **SBOMs (Software Bills of Materials)**, validating software license compliance, and checking cryptographic code signatures before deployment.
* **Practical Task (Generate a Software Bill of Materials [SBOM] / Installed Package Manifest):**
  * **Linux (Debian/Ubuntu):**
    ```bash
    dpkg-query -W -f='\({Package}\t\){Version}\n' | head -n 15
    ```
  * **Python Environment:**
    ```bash
    pip list --format=json | head -n 15
    ```
  * **Windows (PowerShell):**
    ```powershell
    Get-Package | Select-Object -First 15 Name, Version, ProviderName
    ```

### 5. Data Asset Management

## Part B: Assignment, Accounting, Tracking & Monitoring

### 6. Asset Assignment & 7. Asset Accounting
* **Concept:**
  * **Asset Assignment:** Formally binding every laptop, mobile device, server, and software license to a specific **Owner / Custodian** upon provisioning (requiring signed Acceptable Use acknowledgment) so accountability is never ambiguous during an incident.
  * **Asset Accounting:** Maintaining an accurate financial and operational ledger of all hardware/software assets, active licenses (preventing illegal/unpatched pirated software), and depreciation cycles.

### 8. Asset Tracking & 9. Asset Monitoring
* **Concept:**
  * **Asset Tracking:** Continuously recording physical and logical location, serial numbers, MAC addresses, and configuration states inside a **CMDB (Configuration Management Database)** using **Asset Tags / Barcodes**, **RFID**, **GPS/MDM**, and **IPAM (IP Address Management)**.
  * **Asset Monitoring:** Real-time telemetry on asset health, compliance posture, unauthorized configuration drift, and anomalous network activity via **EDR**, **SIEM**, and **NAC**.
* **Practical Task (Extract Hardware Serial Number, UUID & MAC Address for CMDB Enrollment):**
  * **Linux:**
    ```bash
    echo "Hostname  : \$(hostname)"
    echo "Machine ID: \$(cat /etc/machine-id)"
    echo "MAC Addrs : \$(ip -o link show | awk '/link\/ether/ {print \$2, \$17}')"
    sudo dmidecode -s system-serial-number 2>/dev/null || echo "Serial: VM/Virtual"
    ```
  * **Windows (PowerShell):**
    ```powershell
    Get-CimInstance Win32_BIOS | Select-Object Manufacturer, SerialNumber
    Get-NetAdapter | Where-Object Status -eq "Up" | Select-Object Name, MacAddress
    ```

## Part C: Disposal, Decommissioning & Secure Data Destruction

### 10. Asset Disposal & 11. Asset Decommissioning
* **Concept:** Formal end-of-life offboarding procedures when retiring hardware, VMs, or cloud instances:
  * **Asset Decommissioning:** Removing the asset from production networks, revoking TLS certificates and Active Directory/IAM credentials, removing firewall/DNS entries, wiping configurations, and updating the **CMDB** status to `Decommissioned` so retired assets are not flagged as missing/stolen.
  * **Asset Disposal:** Physically recycling, donating, reselling, or destroying retired hardware after certified media sanitization—documenting a **Certificate of Destruction** for audit compliance.

### 12. Secure Data Destruction
* **Concept:** Permanently rendering stored data unrecoverable prior to asset disposal or media reuse, matched to the underlying storage technology:

| Sanitization Method | How It Works | Best Media Fit & Exam Caveats |
| :--- | :--- | :--- |
| **Cryptographic Erasure (Crypto-Shredding)** | Destroying the AES encryption key protecting the volume/drive. | **Best for SSDs, NVMe drives, mobile devices, and Cloud storage** (instantaneous). |
| **Overwriting / Wiping** | Writing patterns of `0`s, `1`s, or pseudorandom bytes across all sectors (`shred`, `dd`). | Effective on magnetic **HDDs**; *unreliable* on SSDs due to wear-leveling reserves. |
| **Purging (Firmware Secure Erase)** | Issuing hardware controller commands (`ATA Secure Erase`, `NVMe Format`) to reset all flash cells. | Effective on modern **SSDs and NVMe drives**. |
| **Degaussing** | Exposing media to an intense electromagnetic field that scrambles magnetic domains. | Effective on magnetic **HDDs and backup tapes**; **completely ineffective on SSDs**. |
| **Physical Destruction** | Shredding, pulverizing, crushing, drilling, or incinerating physical storage media. | Highest assurance for **Top Secret / Restricted** media; renders hardware unusable. |

* **Practical Task (Execute Multi-Pass File Shredding & Verify Destruction via CLI):**
  ```bash
  mkdir -p ~/secplus_asset_lab && cd ~/secplus_asset_lab
  echo "Decommissioned_Server_Secret_Config" > retired_disk_sector.dat

  # Overwrite with 3 random passes, zero final pass (-z), and delete (-u)
  shred -v -n 3 -z -u retired_disk_sector.dat
  ls -la retired_disk_sector.dat 2>&1 || echo "[VERIFIED] File overwritten and destroyed cleanly."
  ```
