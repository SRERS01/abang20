## Part A: Discovery & Vulnerability Identification

### 1. Vulnerability Scanning
* **Concept:** Automated probing of networks, hosts, and web applications to detect missing patches, outdated software versions, open ports, and misconfigurations (using Nessus, OpenVAS, Qualys, or Nmap NSE):
  * **Credentialed (Authenticated) Scan:** Logs into the target OS using read-only service credentials to inspect local registry keys, installed packages, and config files (deepest visibility, lowest false positives).
  * **Non-Credentialed (Unauthenticated) Scan:** Probes externally over the network without login credentials (shows what an external attacker sees).
  * **Intrusive vs. Non-Intrusive:** Non-intrusive checks banners/versions safely; intrusive actively attempts exploitation (risks crashing production services).
* **Practical Task (Run a Safe Service-Version & Vulnerability NSE Scan Against Localhost):**
  ```bash
  # Safe banner/version detection + default non-intrusive scripts on localhost
  nmap -sV --script=default,safe 127.0.0.1
  ```

### 2. IP Address Management (IPAM)
* **Concept:** Centralized planning, tracking, and auditing of IPv4/IPv6 subnets, DHCP leases, and DNS records—ensuring vulnerability scanners maintain complete coverage and immediately spot unauthorized/rogue IP allocations.
* **Practical Task (Simulate IPAM Subnet Allocation & Unscanned IP Gap Detection in Python):**
  ```python
  ipam_allocated = {"10.10.1.10", "10.10.1.11", "10.10.1.12", "10.10.1.99"}
  last_vuln_scan = {"10.10.1.10", "10.10.1.11", "10.10.1.12"}

  unscanned_assets = ipam_allocated - last_vuln_scan
  print("[IPAM COVERAGE GAP] Active IPs missing from vulnerability scanner scope:", unscanned_assets)
  ```

### 3. Cloud Security Posture Management (CSPM)
* **Concept:** Continuous automated auditing of cloud control-plane configurations (AWS, Azure, GCP) to detect public S3/Blob buckets, overly permissive IAM wildcards (`*`), disabled CloudTrail logging, and `0.0.0.0/0` security group rules.
* **Practical Task (Run a Mini CSPM Configuration Auditor in Python):**
  ```python
  cloud_resources = [
      {"id": "sg-prod-ssh",  "type": "SecurityGroup", "port": 22,  "cidr": "0.0.0.0/0"},
      {"id": "s3-kyc-vault", "type": "ObjectStorage", "public": False, "encrypted": True},
      {"id": "trail-main",   "type": "AuditLogging",  "enabled": False}
  ]

  for res in cloud_resources:
      if res["type"] == "SecurityGroup" and res["cidr"] == "0.0.0.0/0" and res["port"] in (22, 3389):
          print(f"[CSPM CRITICAL] {res['id']}: Admin port {res['port']} open to the world!")
      if res["type"] == "AuditLogging" and not res["enabled"]:
          print(f"[CSPM HIGH] {res['id']}: Cloud audit logging is disabled!")
  ```

### 4. Source Code Review
* **Concept:** Inspecting application source code manually (peer review) or automatically (**SAST** — Static Application Security Testing) to catch injection flaws, hardcoded secrets, buffer overflows, and insecure cryptography *before* code compiles or deploys.
* **Practical Task (Static Source Code Review Using Python `ast` & Regex):**
  ```python
  import re

  code_file = 'db_password = "HardcodedPassword2026!"\nquery = "SELECT * FROM users WHERE id=" + user_id'
  if re.search(r'(?i)password\s*=\s*["\'][^"\']+["\']', code_file):
      print("[CODE REVIEW - HIGH] Hardcoded password literal found in source!")
  if re.search(r'SELECT .* \+ ', code_file):
      print("[CODE REVIEW - CRITICAL] String concatenation in SQL query (SQLi risk)!")
  ```

### 5. Vulnerability Identification
* **Concept:** Aggregating findings across vulnerability scanners, CSPM, SAST/DAST, **Software Composition Analysis (SCA)** (third-party library CVEs), and threat intelligence feeds (CISA KEV) into a unified tracking backlog.

## Part B: Assessment, Prioritization & Pen-Test Analysis

### 6. Severity Assessment & 7. Vulnerability Prioritization
* **Concept:**
  * **Severity Assessment:** Scoring technical flaw severity using **CVSS** (`None 0.0`, `Low 0.1–3.9`, `Medium 4.0–6.9`, `High 7.0–8.9`, `Critical 9.0–10.0`).
  * **Vulnerability Prioritization:** Determining **remediation order** in the real world by combining CVSS score with **Active Exploitation (CISA KEV / EPSS)**, **External Internet Exposure**, and **Business Asset Criticality**.
* **Practical Task (Prioritize Remediation Queue Using Contextual Risk Weighting):**
  ```python
  vulns = [
      {"cve": "CVE-2024-1001", "cvss": 9.8, "exposed": False, "in_cisa_kev": False, "asset_tier": "Dev"},
      {"cve": "CVE-2024-2002", "cvss": 8.2, "exposed": True,  "in_cisa_kev": True,  "asset_tier": "Prod"}
  ]

  # CVE-2024-2002 ranks #1 despite lower raw CVSS because it is internet-facing, actively exploited, and on Prod
  ranked = sorted(vulns, key=lambda v: (v["in_cisa_kev"], v["exposed"], v["asset_tier"] == "Prod", v["cvss"]), reverse=True)
  for rank, item in enumerate(ranked, 1):
      print(f"Priority #{rank}: {item['cve']} (CVSS {item['cvss']}, Exposed={item['exposed']}, KEV={item['in_cisa_kev']})")
  ```

### 8. Penetration Testing Report Analysis
* **Concept:** Reviewing an offensive security assessment report containing an **Executive Summary** (business risk overview), **Technical Findings** (exploited attack chains, proof-of-concept steps, CVSS scores), and **Prioritized Remediation Recommendations**—translating attacker exploit paths into defensive engineering tickets.
* **Practical Task:**
  1. Map a sample pen-test finding chain (`Unauthenticated SSRF on /proxy -> Queried Cloud Metadata 169.254.169.254 -> Stole Admin IAM Role Keys`) to **two layered fixes**: (1) Patch SSRF URL allow-listing in app code, and (2) Enforce **IMDSv2** token requirement on cloud VMs.

## Part C: Remediation & Verification

### 9. Vulnerability Remediation
* **Concept:** Eliminating or reducing the vulnerability via **Patching/Updating**, **Configuration Hardening** (disabling weak TLS/ports), **Code Fixes** (parameterized queries), **Asset Decommissioning**, or applying **Compensating Controls** (WAF virtual patching / VLAN isolation) when immediate patching is impossible.

### 10. Vulnerability Verification
* **Concept:** Confirming a fix actually worked and did not break functionality—accomplished through **Rescanning** the target host, verifying **Audit/Configuration Logs**, and executing **Regression / Functional Testing** before closing the remediation ticket.
* **Practical Task (Simulate Pre-Patch Detection → Remediation → Post-Patch Verification):**
  ```python
  # 1. Pre-patch config state
  sshd_config = {"PermitRootLogin": "yes", "Protocol": "2"}

  # 2. Remediation applied
  sshd_config["PermitRootLogin"] = "no"

  # 3. Verification check before closing ticket
  assert sshd_config["PermitRootLogin"] == "no", "Verification Failed!"
  print("[VERIFIED] Rescan confirms PermitRootLogin is hardened to 'no'. Ticket eligible for closure.")
  ```

## Part D: Reporting & Responsible Disclosure

### 11. Vulnerability Reporting (Internal vs. External)
* **Concept:**
  * **12. Internal Vulnerability Reporting:** Delivering recurring SLA compliance dashboards, aging vulnerability metrics, and technical remediation tickets to internal IT ops, developers, and senior leadership.
  * **13. External Vulnerability Reporting:** Submitting vulnerability reports to external software/hardware vendors, national CERTs/CSIRTs, or regulatory bodies when flaws are discovered in third-party products or breach thresholds are met.

### 14. Bug Bounty Programs & 15. Responsible Disclosure
* **Concept:**
  * **Bug Bounty Programs:** Authorized crowdsourced security programs (e.g., HackerOne, Bugcrowd, corporate `security.txt` programs) offering financial rewards and **Safe Harbor** legal protection to ethical researchers who report valid vulnerabilities within defined rules of engagement.
  * **Responsible (Coordinated) Disclosure:** Ethical practice where a researcher privately reports a newly discovered vulnerability to the affected vendor and grants an agreed remediation window (commonly **45–90 days**) to develop and release a patch *before* publishing technical exploit details publicly.
* **Practical Task (Inspect a Live Domain's RFC 9116 `security.txt` Disclosure Policy):**
  ```bash
  # Check how organizations publish official vulnerability disclosure contacts & policies
  curl -sL https://google.com | head -n 12
  ```
