## Part A: Monitoring Scopes & Log Lifecycle

### 1. System Monitoring, 2. Application Monitoring & 3. Infrastructure Monitoring
* **Concept:**
  * **System Monitoring:** Tracking OS-level health and security telemetry on endpoints/servers (CPU/RAM spikes, service crashes, privileged logins, registry/file modifications).
  * **Application Monitoring (APM):** Tracking web/app-layer metrics and security logs (HTTP `401/403/500` error spikes, API latency, database query errors, authentication anomalies).
  * **Infrastructure Monitoring:** Tracking network and core platform availability (switch/router uptime, firewall throughput, VPN tunnel status, cloud resource health).
* **Practical Task (Query System & Application Logs via CLI):**
  * **Linux (`systemd` / `journalctl`):**
    ```bash
    journalctl -p err -n 10 --no-pager
    ```
  * **Windows (PowerShell):**
    ```powershell
    Get-WinEvent -LogName Application -MaxEvents 5 | Select-Object TimeCreated, Id, LevelDisplayName, Message
    ```

### 4. Log Aggregation, 5. Alert Generation, 6. Security Scanning, 7. Log Archiving & 8. Security Reporting
* **Concept:**
  * **Log Aggregation:** Collecting and centralizing logs from distributed endpoints, firewalls, cloud services, and apps into a single repository (SIEM/log collector) with synchronized **NTP** timestamps.
  * **Alert Generation:** Triggering real-time notifications when aggregated events match correlation rules or anomaly thresholds.
  * **Security Scanning:** Scheduled network, vulnerability, and configuration scans feeding compliance and exposure telemetry into monitoring platforms.
  * **Log Archiving:** Compressing, encrypting, and storing historical logs in immutable cold storage (e.g., WORM S3 buckets) for compliance audits (PCI-DSS, HIPAA) and long-term forensic investigations.
  * **Security Reporting:** Summarizing incident trends, SLA metrics, mean-time-to-detect (**MTTD**), and compliance posture for SOC leads and executives.
* **Practical Task (Aggregate, Normalize & Archive Logs with SHA-256 Integrity Verification in Python):**
  ```python
  import json, hashlib

  raw_logs = [
      "Nov 21 14:01:02 web01 sshd[1201]: Failed password for root from 198.51.100.42",
      "Nov 21 14:01:05 web01 sshd[1201]: Failed password for root from 198.51.100.42"
  ]

  normalized = [{"host": line.split(), "service": "sshd", "event": "AUTH_FAIL", "src_ip": line.split()[-1]} for line in raw_logs]
  archive_blob = json.dumps(normalized, indent=2).encode()

  with open("archived_logs_2026-11-21.json", "wb") as f:
      f.write(archive_blob)

  print("Archived Log SHA-256 Integrity Hash:", hashlib.sha256(archive_blob).hexdigest())
  ```

## Part B: Alert Tuning, Benchmarks & Collection Architectures

### 9. Alert Tuning
* **Concept:** Refining SIEM/IDS correlation rules and thresholds to minimize **False Positives** (benign activity triggering noisy alerts, causing **alert fatigue**) and **False Negatives** (real attacks slipping past undetected).
* **Practical Task (Reduce False Positives by Adding an Authorized Vulnerability Scanner Allow-List in Python):**
  ```python
  authorized_scanners = {"10.10.50.5"}  # Internal Nessus Scanner IP
  port_scan_alerts = [
      {"src_ip": "10.10.50.5",    "ports_probed": 1000},
      {"src_ip": "203.0.113.99",  "ports_probed": 1000}
  ]

  for alert in port_scan_alerts:
      if alert["src_ip"] in authorized_scanners:
          print(f"[TUNED / SUPPRESSED] Expected scan from authorized scanner {alert['src_ip']}")
      else:
          print(f"[TRUE POSITIVE ALERT] Unauthorized port scan from {alert['src_ip']}!")
  ```

### 10. Security Benchmarks & 22. SCAP (Security Content Automation Protocol)
* **Concept:**
  * **Security Benchmarks:** Standardized, vendor-neutral configuration hardening baselines (e.g., **CIS Benchmarks**, **DISA STIGs**).
  * **SCAP:** NIST suite of interoperable XML/JSON standards (**OVAL**, **XCCDF**, **CVE**, **CCE**, **CPE**, **CVSS**) enabling automated vulnerability and configuration compliance scanning against CIS/STIG benchmarks (e.g., OpenSCAP).
* **Practical Task (Inspect OpenSCAP / Local Configuration Compliance Check):**
  ```bash
  # Check if OpenSCAP (oscap) is installed or verify a basic CIS benchmark setting (e.g., core dumps disabled)
  sysctl fs.suid_dumpable
  ```

### 11. Agent-Based Monitoring vs. 12. Agentless Monitoring
* **Concept:**
  * **Agent-Based Monitoring:** Installs a lightweight software daemon directly on each endpoint (Sysmon, Wazuh, CrowdStrike, Splunk Universal Forwarder)—provides deep process/registry/memory telemetry and local buffering when offline, **but** requires deployment and maintenance overhead.
  * **Agentless Monitoring:** Collects telemetry remotely via standard network protocols (**WMI, WinRM, SSH, SNMP, APIs**) without installing software on endpoints—ideal for IoT/OT devices, network switches, and rapid cloud discovery, **but** offers shallower host-level visibility.

## Part D: Network Telemetry Protocols & Traffic Visibility

### 19. NetFlow (and IPFIX / sFlow)
* **Concept:** Network protocol developed by Cisco that records **IP traffic flow metadata** (Source/Dest IP, Source/Dest Port, Protocol, Byte/Packet Count, Timestamps)—**without capturing full packet payloads**. Ideal for detecting DDoS spikes, port scans, and large data exfiltration transfers across high-speed backbones.

### 20. SNMP (Simple Network Management Protocol)
* **Concept:** Protocol (`UDP/161` queries, `UDP/162` Traps) used to monitor and manage switches, routers, firewalls, printers, and UPS units.
  * *Security Critical:* **SNMPv1 and SNMPv2c** transmit community strings (`public`/`private`) in **cleartext**! Always enforce **SNMPv3**, which provides authentication (`SHA`) and encryption (`AES`).

### 21. Syslog
* **Concept:** Standard protocol (`UDP/514` plaintext, **`TCP/6514` encrypted over TLS**) used by Linux servers, firewalls, and network appliances to forward timestamped event messages with **Facility** and **Severity levels (`0` Emergency to `7` Debug)** to a central log server.
* **Practical Task (Generate a Custom Local Syslog Entry & Verify It in System Logs):**
  ```bash
  logger -p auth.warning -t SECPLUS_LAB "Simulated unauthorized privilege escalation attempt"
  sudo tail -n 5 /var/log/syslog 2>/dev/null || journalctl -t SECPLUS_LAB -n 5 --no-pager
  ```

### 23. Automated Alerts, 24. Port Mirroring, 25. Security Dashboards & 26. Network Management Systems (NMS)
* **Concept:**
  * **Automated Alerts:** Real-time notifications dispatched via email, SMS, Slack/Teams webhooks, or PagerDuty when high-severity SIEM/NMS rules trigger.
  * **Port Mirroring (SPAN — Switched Port Analyzer):** Configuring a network switch to copy all frames from one or more source ports/VLANs to a dedicated monitoring port connected to a **NIDS** or **Packet Analyzer** *(or using a physical hardware **Network TAP**)*.
  * **Security Dashboards:** Visual SOC interfaces displaying real-time KPIs—open critical alerts, top attacking IPs, patch SLA compliance, and MITRE ATT&CK coverage.
### 23. Automated Alerts
* **Concept:** Real-time notifications automatically triggered and dispatched by a **SIEM**, **SOAR**, **EDR**, or **NMS** when correlation rules, anomaly thresholds, or device health checks breach defined limits.
  * *Delivery Channels:* Email, SMS, Slack/Microsoft Teams webhooks, PagerDuty/Opsgenie on-call escalation, or automated ITSM ticket creation (ServiceNow/Jira).
  * *Exam Best Practice:* Automated alerts must include **actionable context** (affected host, source/destination IP, MITRE ATT&CK tactic, timestamp, and recommended triage playbook) to accelerate Mean Time to Acknowledge (**MTTA**) and prevent alert fatigue.
* **Practical Task (Build a Structured JSON Webhook Alert Dispatcher in Python):**
  ```python
  import json
  from datetime import datetime, timezone

  def dispatch_automated_alert(rule_name, severity, src_ip, target_host, action_taken):
      alert_payload = {
          "timestamp_utc": datetime.now(timezone.utc).isoformat(),
          "alert_title": rule_name,
          "severity": severity,
          "indicators": {"source_ip": src_ip, "affected_host": target_host},
          "soar_automated_action": action_taken
      }
      # In production, this JSON payload is POSTed to a Slack/Teams/PagerDuty webhook URL
      print("=== AUTOMATED SOC ALERT DISPATCHED ===")
      print(json.dumps(alert_payload, indent=2))

  dispatch_automated_alert(
      rule_name="Outbound Cobalt Strike C2 Beacon Detected",
      severity="CRITICAL",
      src_ip="198.51.100.88",
      target_host="FIN-WKSTN-014",
      action_taken="Host isolated via EDR API & C2 IP blocked on Edge Firewall"
  )
  ```

### 24. Port Mirroring (SPAN vs. Network TAP)
* **Concept:** Capturing live network traffic flowing across a switch for passive inspection by a **NIDS**, **SIEM sensor**, or **Packet Analyzer (Wireshark / Zeek)** without interrupting production traffic:
  * **Port Mirroring (SPAN — Switched Port Analyzer / RSPAN):** Software configuration on a managed switch that copies frames from specified source ports or VLANs to a destination monitoring port. *(Limitation: Under heavy traffic load, switches may drop mirrored packets because switching production frames takes priority).*
  * **Network TAP (Test Access Point):** Dedicated physical hardware splitter installed inline on a fiber or copper cable that duplicates 100% of electrical/optical signals to monitoring tools with zero packet drops and complete invisibility to attackers (no IP/MAC address).
* **Practical Task (Simulate Promiscuous Interface Capture with `tcpdump`):**
  ```bash
  # Capture 10 packets on a local interface as a passive NIDS/SPAN sensor would inspect them
  sudo tcpdump -i any -nn -c 10
  ```

### 26. Network Management Systems (NMS)
* **Concept:** Centralized operational monitoring platforms (e.g., **Zabbix, Nagios, SolarWinds, PRTG, LibreNMS**) that continuously poll and receive alerts from switches, routers, firewalls, servers, and UPS units using **SNMPv3**, **ICMP**, **Syslog**, and **NetFlow**.
  * *Security Relevance:* Sudden spikes in interface bandwidth (DDoS or massive data exfiltration), unexpected device reboots, high CPU utilization (cryptomining), or unauthorized configuration changes on core routers are often spotted first in the **NMS**.
* **Practical Task (Check Local Interface Traffic Counters & Link Uptime Telemetry):**
  * **Linux:**
    ```bash
    ip -s link show | head -n 15
    ```
  * **Windows (PowerShell):**
    ```powershell
    Get-NetAdapterStatistics | Select-Object Name, ReceivedBytes, SentBytes, ReceivedDiscardedPackets
    ```

## Quick-Reference Exam Matrix: Network Telemetry & Monitoring Protocols

| Protocol / Mechanism | Default Port(s) | What It Captures / Does | Security Best Practice |
| :--- | :--- | :--- | :--- |
| **Syslog** | `UDP/514` (Plaintext)<br>`TCP/6514` (TLS) | Event logs from Linux, firewalls, routers, and appliances (`0` Emergency – `7` Debug). | Always encrypt log forwarding over **TLS (`TCP/6514`)** and sync clocks via **NTP**. |
| **SNMP** | `UDP/161` (Polling)<br>`UDP/162` (Traps) | Device hardware metrics, interface status, CPU/RAM, and UPS battery alerts. | Disable SNMPv1/v2c (cleartext community strings); enforce **SNMPv3** (Auth + AES encryption). |
| **NetFlow / IPFIX** | `UDP/2055` (Common) | IP conversation **metadata** (Src/Dst IP, Ports, Byte/Packet counts)—no packet payloads. | Use for high-speed DDoS detection, lateral movement mapping, and exfiltration volume alerts. |
| **SPAN / Network TAP** | Layer 1 / Layer 2 | Copies full network frames (headers + payloads) to NIDS or Wireshark. | Use **Network TAPs** on critical links where zero packet loss is mandatory. |
| **SCAP** | XML / JSON Standards | Automates configuration compliance & vulnerability checks (`OVAL`, `XCCDF`, `CVE`, `CVSS`). | Pair with **CIS Benchmarks** / **DISA STIGs** for automated continuous compliance auditing. |
