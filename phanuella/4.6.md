## Part A: Core Automation & Orchestration Capabilities

### 1. Security Automation
* **Concept:** Using scripts, SOAR playbooks, and APIs to execute repetitive security tasks automatically without human intervention (e.g., blocking malicious IPs, quarantining phishing emails, isolating infected endpoints via EDR).
* **Practical Task (Automated Malicious IP Blocklist & SIEM Enrichment Script in Python):**
  ```python
  threat_feed_ips = {"198.51.100.88", "203.0.113.44"}
  firewall_blocked = set()

  def auto_contain_ip(src_ip):
      if src_ip in threat_feed_ips and src_ip not in firewall_blocked:
          firewall_blocked.add(src_ip)
          return f"[SOAR ACTION] Added {src_ip} to Edge Firewall Deny List."
      return f"[NO ACTION] {src_ip} clean or already blocked."

  print(auto_contain_ip("198.51.100.88"))
  ```

### 2. User Provisioning Automation
* **Concept:** Connecting HR identity systems (Workday, BambooHR) to Identity Providers (Entra ID, Okta, Active Directory) via **SCIM (System for Cross-domain Identity Management)** to automatically create accounts, assign role-based groups on hire, update permissions on role transfer, and revoke all tokens immediately upon termination.

### 3. Resource Provisioning
* **Concept:** Automatically spinning up, configuring, and tearing down servers, cloud VPCs, containers, and security groups on demand via **Infrastructure as Code (IaC)** templates (Terraform, CloudFormation, Ansible) rather than manual console clicks.

### 4. Desired-State Management (Configuration Management)
* **Concept:** Defining a hardened target configuration baseline in code (using **Ansible**, **Puppet**, **Chef**, or **PowerShell DSC**) and continuously polling systems to detect and automatically remediate **configuration drift** (e.g., re-enabling a firewall if an admin accidentally disabled it).
* **Practical Task (Implement a Desired-State Drift Detector & Auto-Remediator in Python):**
  ```python
  desired_state = {"PermitRootLogin": "no", "PasswordAuthentication": "no", "FirewallEnabled": True}
  current_state = {"PermitRootLogin": "yes", "PasswordAuthentication": "no", "FirewallEnabled": False}

  for setting, expected in desired_state.items():
      if current_state[setting] != expected:
          print(f"[DRIFT DETECTED] '{setting}' was '{current_state[setting]}' -> Auto-remediating to '{expected}'")
          current_state[setting] = expected
  ```

### 5. Anomaly Detection
* **Concept:** Establishing normal statistical/behavioral baselines (login hours, outbound bandwidth, process trees) and automatically flagging deviations that static signature rules miss.

### 6. Ticket Management
* **Concept:** Automatically creating, enriching, deduplicating, routing, and closing incident/remediation tickets in ITSM platforms (ServiceNow, Jira) with attached IoCs, packet captures, and SLA timers.

## Part B: Automation Governance, Guardrails & Risks

### 7. Automation Guardrails & 8. Automation Logic
* **Concept:**
  * **Automation Logic:** Conditional decision trees (`IF / ELSE`, thresholds, confidence scores, severity branching) governing how a SOAR playbook reacts to different alert types.
  * **Automation Guardrails:** Hard safety boundaries preventing runaway scripts from causing self-inflicted outages—such as **Human-in-the-Loop (HITL) approval gates** before isolating Tier-0 Domain Controllers, **blast-radius caps** (never block more than 10 IPs/min), and **protected allow-lists** (never block internal DNS/gateway IPs).
* **Practical Task (Implement a Protected Allow-List & Tier-0 Asset Guardrail in Python):**
  ```python
  protected_infrastructure = {"10.0.0.1", "8.8.8.8", "DC01.corp.local"}

  def guarded_isolation(target):
      if target in protected_infrastructure:
          return f"[GUARDRAIL TRIGGERED] Blocked automated isolation of critical asset '{target}'! Escalating to Tier-3 Human Analyst."
      return f"[EXECUTED] Isolated host '{target}'."

  print(guarded_isolation("DC01.corp.local"))
  print(guarded_isolation("WKSTN-109.corp.local"))
  ```

* **Concept:**
  * **Predictive Analysis:** Machine learning models forecasting emerging attack trends, likely target assets, or impending hardware/capacity failures based on historical telemetry and threat intelligence.
  * **AI-Augmented Baselines:** Dynamically adapting behavioral profiles for every user, host, and network segment (UEBA) to spot subtle zero-day lateral movement or insider data staging without manual threshold tuning.
* **Practical Task (Simulate an AI-Augmented Z-Score Baseline Anomaly Detector in Python):**
  ```python
  import statistics

  # Historical daily outbound upload MB for a finance workstation
  baseline_mb = [45, 52, 48, 50, 47, 53, 49]
  today_upload_mb = 620

  mean = statistics.mean(baseline_mb)
  stdev = statistics.stdev(baseline_mb)
  z_score = (today_upload_mb - mean) / stdev

  if z_score > 3.0:
      print(f"[AI BASELINE ANOMALY] Upload of {today_upload_mb}MB is {z_score:.1f} std devs above normal ({mean:.1f}MB)!")
  ```

### 1. Continuous Integration (CI) & 2. Continuous Deployment (CD)
* **Concept:** Automated DevSecOps software delivery pipelines that enforce security gates at every stage of the Software Development Life Cycle (SDLC):
  * **Continuous Integration (CI):** Developers frequently merge code changes into a shared Git repository. Each commit automatically triggers a build pipeline that runs **unit tests**, **Secrets Scanning**, **SAST (Static Application Security Testing)**, and **SCA (Software Composition Analysis)** to catch vulnerable third-party libraries early.
  * **Continuous Deployment (CD):** Code that passes all CI security gates is cryptographically signed, packaged (e.g., hardened container image), and automatically deployed to staging/production—running **DAST (Dynamic Application Security Testing)** and health checks with instant automated rollback if anomalies appear.

* **Practical Task (Build & Test a Local Git Pre-Commit CI/CD Security Gate):**
  Run this lab to wire a real **Git pre-commit hook** that blocks developers from committing hardcoded secrets or unsafe `eval()` functions into a repository:
  ```bash
  mkdir -p ~/secplus_devsecops_lab && cd ~/secplus_devsecops_lab
  git init -q

  # Create an automated CI Security Hook inside .git/hooks/pre-commit
  cat << 'EOF' > .git/hooks/pre-commit
  #!/bin/bash
  echo "[CI SECURITY GATE] Scanning staged files for hardcoded secrets & unsafe functions..."
  STAGED_FILES=$(git diff --cached --name-only)

  for FILE in $STAGED_FILES; do
      if grep -nE "AKIA[0-9A-Z]{16}|eval\(|password\s*=\s*['\"][^'\"]+['\"]" "$FILE"; then
          echo "[CI BLOCKED] Security violation found in $FILE! Fix before committing."
          exit 1
      fi
  done

  echo "[CI PASSED] All security checks passed. Proceeding with commit/CD pipeline."
  exit 0
  EOF

  chmod +x .git/hooks/pre-commit

  # Test 1: Attempt to commit vulnerable code (Should be BLOCKED by CI gate)
  echo 'API_SECRET = "AKIAIOSFODNN7EXAMPLE"' > app.py
  git add app.py
  git commit -m "Test vulnerable commit" || echo "[VERIFIED] CI Gate blocked leaked secret!"

  # Test 2: Fix code to use environment variables and commit cleanly (Should PASS)
  echo 'import os; API_SECRET = os.getenv("API_SECRET")' > app.py
  git add app.py
  git commit -m "SecOps: Load API_SECRET securely from environment"
  ```

### 3. Automated Workflows
* **Concept:** End-to-end, event-driven sequences (**SOAR Playbooks**) chaining detection triggers, enrichment lookups, conditional logic, guardrails, and containment actions without human delay:
  * *Example Workflow:* `Phishing Email Reported` → `Extract URLs & Attachment Hashes` → `Query Threat Intel API` → `If Malicious: Quarantine Email Across All Mailboxes + Block Domain on Proxy + Open SOC Ticket`.
* **Practical Task (Build a Multi-Step Event-Driven SOAR Workflow in Python):**
  ```python
  import hashlib

  def run_phishing_workflow(email_subject, attachment_bytes, sender_ip):
      print(f"[TRIGGER] Investigating reported email: '{email_subject}'")

      # Step 1: Compute artifact hash
      sha256 = hashlib.sha256(attachment_bytes).hexdigest()
      known_malware_hashes = {"5e884898da28047151d0e56f8dc6292773603d0d6aabbdd62a11ef721d1542d8"}

      # Step 2: Decision Logic & Containment Actions
      if sha256 in known_malware_hashes:
          print(f"  [ENRICHMENT] Hash {sha256[:16]}... matched known Trojan!")
          print(f"  [ACTION 1] Purged email from all employee inboxes.")
          print(f"  [ACTION 2] Blocked sender IP {sender_ip} at perimeter firewall.")
          print(f"  [ACTION 3] Created High-Priority Incident Ticket #INC-4092.")
      else:
          print("  [RESULT] Attachment clean; closed ticket as benign.")

  run_phishing_workflow("Urgent Invoice Attached", b"password", "198.51.100.77")
  ```

### 4. Integrations
* **Concept:** Connecting independent security, IT, and cloud platforms so they share real-time telemetry and execute coordinated actions automatically via **REST APIs**, **Webhooks**, **Syslog**, and **STIX/TAXII** threat-intelligence feeds.
  * *Common SecOps Integrations:*
    * **SIEM $\leftrightarrow$ SOAR:** SIEM forwards high-confidence correlation alerts to SOAR for automated response.
    * **SOAR $\leftrightarrow$ EDR / Firewall / IdP:** SOAR calls vendor REST APIs to isolate compromised endpoints, push firewall IP blocks, or revoke compromised OAuth/SSO sessions.
    * **HRIS $\leftrightarrow$ Identity Provider (SCIM):** Automates user onboarding and immediate termination deprovisioning.
    * **CI/CD Pipeline $\leftrightarrow$ SAST / SCA / Container Registry:** Blocks vulnerable builds before reaching production.
