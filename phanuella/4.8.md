## Part A: Log and Trace Data (12 Sources)

| Data Source | What It Records | Practical CLI / Investigation Check |
| :--- | :--- | :--- |
| **1. Access Logs** | HTTP/web server requests, file-share reads/writes, VPN connections, and resource access timestamps (`GET`/`POST`, status codes `200`/`403`/`404`). | `tail -n 10 /var/log/nginx/access.log` (or Apache `access.log`) |
| **2. Accounting Logs** | Session duration, bandwidth consumed, RADIUS/TACACS+ billing/usage telemetry, and user resource consumption. | `last -w \| head -n 10` (shows user session login/logout durations) |
| **3. Physical Access Logs** | RFID badge swipes, biometric door readers, turnstile entries, visitor sign-in sheets, and server cage unlocks. | Cross-reference badge timestamps against VPN logins (**Impossible Travel / Tailgating**). |
| **4. Device Logs** | Local hardware/appliance logs from routers, switches, firewalls, IoT devices, and mobile phones (interface flaps, boot errors, config changes). | `dmesg \| tail -n 10` |
| **5. Server Logs** | OS daemon events, web/database/mail server health, scheduled task executions (`cron`), and service crashes. | `journalctl -u ssh -n 10 --no-pager` |
| **6. Application Logs** | Custom business app events, API errors, SQL exceptions, stack traces, and app-level privilege changes. | `Get-WinEvent -LogName Application -MaxEvents 5` (PowerShell) |
| **7. Authentication Logs** | Logon successes/failures, MFA challenges, Kerberos TGT requests, and `sudo` escalations (`Event ID 4624/4625` on Windows; `/var/log/auth.log` on Linux). | `sudo grep -iE "accepted|failed" /var/log/auth.log \| tail -n 10` |
| **8. Communication Logs** | Email gateway headers/SMTP routing logs, VoIP call detail records (CDRs), and instant messaging/collaboration audit trails. | Inspect SMTP `Received:` headers & SPF/DKIM results during BEC probes. |
| **9. Audit Logs** | High-assurance security trail tracking policy changes, user/group modifications, ACL updates, and object access (`Event ID 4720/4732` on Windows; `auditd` on Linux). | `sudo ausearch -m USER_ACCT -ts today 2>/dev/null \|\| lastlog \| head -n 10` |
| **10. Endpoint Logs** | Workstation/laptop telemetry from **EDR**, **Sysmon** (process creation `ID 1`, network connections `ID 3`, registry edits `ID 13`), and antivirus quarantine logs. | `Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 5` |
| **11. Network Logs** | Firewall accept/deny ACL hits, IDS/IPS signature alerts, DNS query logs, DHCP lease tables, and proxy URL logs. | `sudo grep -i "UFW BLOCK" /var/log/syslog \| tail -n 5` |
| **12. Metadata** | "Data about data"—file MACB timestamps, EXIF camera/GPS tags in images, email routing headers, and packet flow headers without inspecting full content. | `stat /etc/passwd` (or `exiftool suspect_photo.jpg`) |

* **Practical Task (Extract File Metadata & Timestamps via CLI):**
  ```bash
  echo "Suspicious Document Content" > leak_evidence.txt
  stat leak_evidence.txt
  ```

## Part B: Investigation Data Sources (8 Operational & Network Sources)

### 1. Vulnerability Scan Results & 2. Automated Security Reports
* **Concept:** Historical Nessus/OpenVAS/Qualys scan exports and scheduled SIEM/EDR/CSPM compliance summaries—used during an incident to determine **which CVE existed on the compromised host at the time of breach**.

### 3. NetFlow & 4. IPFIX (IP Flow Information Export)
* **Concept:** Network flow telemetry capturing **conversation metadata** (Source/Dest IP, Source/Dest Port, Protocol, Byte/Packet Count, Start/End Timestamps) without recording full packet payloads. **IPFIX** is the open IETF standard evolved from Cisco **NetFlow v9**. Crucial for spotting large outbound data exfiltration spikes and C2 beaconing intervals.
* **Practical Task (Detect Outbound Data Exfiltration Spikes in Simulated NetFlow/IPFIX Records in Python):**
  ```python
  netflow_records = [
      {"src": "10.10.1.15", "dst": "142.250.190.46", "dst_port": 443, "bytes_out": 45_000},
      {"src": "10.10.1.22", "dst": "198.51.100.88",  "dst_port": 443, "bytes_out": 8_500_000_000}  # 8.5 GB!
  ]

  for flow in netflow_records:
      if flow["bytes_out"] > 1_000_000_000:
          print(f"[IPFIX EXFILTRATION ALERT] Host {flow['src']} transferred {flow['bytes_out']/1e9:.2f} GB to {flow['dst']}!")
  ```

### 5. Surveillance Footage
* **Concept:** Time-synchronized CCTV video recordings from entrances, server rooms, and loading docks—correlated with physical badge logs to confirm **who physically sat at a workstation** or tailgated into a restricted zone during an insider incident.

### 6. Security Tools, 7. Dashboards & 8. Packet Captures (PCAPs)
* **Concept:**
  * **Security Tools & Dashboards:** Unified consoles across **SIEM**, **EDR**, **SOAR**, **DLP**, and **WAF** providing correlated timelines, process trees, and visual anomaly spikes.
  * **Packet Captures (`.pcap` / `.pcapng`):** Full-frame network recordings analyzed in **Wireshark** or **`tcpdump`** to reconstruct TCP streams, extract dropped malware binaries over HTTP/SMB, and prove exact payload execution.
* **Practical Task (Capture & Inspect a Live `.pcap` File with `tcpdump`):**
  ```bash
  sudo tcpdump -i any -nn -c 15 "port 53 or port 443" -w investigation_capture.pcap
  tcpdump -nn -r investigation_capture.pcap | head -n 10
  ```

## Part C: Digital Evidence, Preservation & Investigation Stakeholders

### 1. File and Log Integrity
* **Concept:** Proving digital evidence has not been altered since collection using cryptographic hashes (**SHA-256** / **SHA-512**) and write-once (**WORM**) storage. If even one bit changes, the hash fails verification.

### 2. System Images, 3. Memory Dumps, 4. Bit-Level Copies & 5. System Snapshots
* **Concept:**
  * **Memory Dumps:** Capturing volatile **RAM** first (`LiME` on Linux, `FTK Imager` / `DumpIt` on Windows) to recover decrypted passwords, encryption keys, active C2 sockets, and **fileless malware** before powering down.
  * **Bit-Level Copies (Bit-Stream Forensic Images):** Sector-by-sector exact clone (`dd`, `dcfldd`, `FTK Imager`) of a physical drive—capturing active files, **deleted files in unallocated space**, and **file slack space** (unlike a standard file copy).
  * **System Images:** Full OS/disk image snapshots used for forensic cloning or rapid clean golden-image restoration.
  * **System Snapshots:** Point-in-time state captures of a Virtual Machine (VMware/VirtualBox) or Cloud volume (AWS EBS Snapshot) capturing both disk state and active VM memory (`.vmem`) instantaneously for offline forensic analysis.
* **Practical Task (Create a Bit-Level Sector Image & Verify SHA-256 Integrity via `dd`):**
  ```bash
  mkdir -p ~/secplus_forensics_lab && cd ~/secplus_forensics_lab

  # 1. Create a simulated 1MB raw storage device image containing hidden/deleted data
  dd if=/dev/zero of=suspect_usb.img bs=1M count=1 status=none
  echo "DELETED_SECRET_KEY=99887766" | dd of=suspect_usb.img conv=notrunc status=none

  # 2. Acquire a Bit-Level Forensic Copy & compute SHA-256 hashes of original vs. forensic clone
  dd if=suspect_usb.img of=forensic_clone.dd bs=4096 status=none
  sha256sum suspect_usb.img forensic_clone.dd
  ```

### 6. Evidence Preservation
* **Concept:** Protecting artifacts from accidental modification or spoliation using **Hardware Write-Blockers**, **Order of Volatility** collection, **Litigation Holds**, and strict **Chain of Custody** logs.

### 7. Log Parsing
* **Concept:** Extracting, normalizing, and correlating timestamps, IP addresses, user IDs, and event codes across disparate log formats (`Syslog`, `JSON`, `XML`, `CSV`) to build a unified attack timeline.
* **Practical Task (Cross-Log Timeline Correlation Script in Python):**
  ```python
  # Correlate Physical Badge Log + VPN Auth Log + Endpoint EDR Log into a unified forensic timeline
  timeline_events = [
      {"ts": "2026-11-21T08:02:10Z", "source": "Physical_Badge", "detail": "Badge #402 (Ambe Fon) entered Main Lobby"},
      {"ts": "2026-11-21T08:05:44Z", "source": "Auth_Log",       "detail": "SSH login accepted for 'ambe' from 10.10.1.15"},
      {"ts": "2026-11-21T08:06:12Z", "source": "Endpoint_EDR",   "detail": "Process 'python3 audit.py' executed"}
  ]

  for ev in sorted(timeline_events, key=lambda x: x["ts"]):
      print(f"{ev['ts']} | [{ev['source']:<14}] | {ev['detail']}")
  ```

## Part D: Investigation Stakeholders (3 Cross-Functional Teams)

> **Exam Tip:** CompTIA Security+ scenario questions frequently describe a specific type of incident—such as an employee stealing trade secrets, a fraudulent wire transfer, or a regulatory data breach—and ask **which internal department** the security team must engage alongside technical responders.

| Investigation Stakeholder | Core Responsibilities & When to Engage | Key Exam Triggers |
| :--- | :--- | :--- |
| **1. Human Resources (HR)** | • Guides internal investigations involving **employees or contractors**.<br>• Advises on labor laws, employee privacy rights, union rules, and disciplinary procedures.<br>• Coordinates confidential **employee interviews** and ensures immediate **account deprovisioning** upon termination.<br>• Executes background checks and Acceptable Use Policy (AUP) enforcement. | • Insider threat / data exfiltration by staff<br>• AUP violation (e.g., unauthorized crypto mining or harassment)<br>• Disgruntled employee sabotage |
| **2. Accounts Department (Finance)** | • Investigates **unauthorized wire transfers**, invoice fraud, payroll manipulation, and **Business Email Compromise (BEC)**.<br>• Freezes compromised bank accounts, recalls fraudulent payments, and audits financial transaction logs.<br>• Tracks total incident response, downtime, and recovery costs for **cyber insurance claims** and executive loss reporting. | • BEC / CEO fraud wire transfer<br>• Ransomware extortion payment evaluation<br>• Financial embezzlement or ERP tampering |
| **3. Legal Department** | • Determines **mandatory regulatory reporting deadlines** (e.g., 72-hour GDPR breach notification, HIPAA, SEC, national data protection laws).<br>• Issues **Litigation Holds** to suspend normal data deletion and preserve **E-Discovery** records.<br>• Ensures **Chain of Custody** and forensic collection meet courtroom admissibility standards.<br>• Protects forensic reports under **attorney-client privilege** and coordinates with **Law Enforcement**. | • Confirmed PII/PHI customer data breach<br>• Subpoenas, lawsuits, or regulatory inquiries<br>• Engaging external forensic firms or law enforcement |

* **Practical Task (Build an Automated Investigation Stakeholder Escalation Router in Python):**
  ```python
  incidents = [
      {"id": "INV-101", "summary": "Senior engineer copied R&D source code to personal USB before resigning", "tags": ["insider", "employee"]},
      {"id": "INV-102", "summary": "Spoofed CFO email tricked clerk into wiring \$85,000 to external account",     "tags": ["bec", "wire_fraud"]},
      {"id": "INV-103", "summary": "Misconfigured S3 bucket exposed 50,000 customer PII records externally",     "tags": ["pii_breach", "external"]}
  ]

  def route_stakeholders(incident):
      stakeholders = ["SOC / Incident Commander"]
      if "employee" in incident["tags"] or "insider" in incident["tags"]:
          stakeholders.append("Human Resources (HR)")
      if "bec" in incident["tags"] or "wire_fraud" in incident["tags"]:
          stakeholders.append("Accounts Department (Finance)")
      if "pii_breach" in incident["tags"] or "insider" in incident["tags"]:
          stakeholders.append("Legal Department")
      return stakeholders

  print("=== INVESTIGATION STAKEHOLDER ESCALATION MATRIX ===")
  for inc in incidents:
      print(f"{inc['id']} | {inc['summary']}")
      print(f"   -> Engage: {', '.join(route_stakeholders(inc))}\n")
  ```
