## Part B: Standards (5 Mandatory Technical Requirements)

> **Exam Tip:** **Policies** state *what* leadership mandates; **Standards** define the specific, measurable, **mandatory** technical metrics (`AES-256`, `14 characters`, `TLS 1.3`) required to satisfy the policy.

### 1. Security Baselines
* **Concept:** Minimum approved, uniform configuration states established for every OS, server, container, or cloud image before production deployment (used to detect configuration drift).
### 2. Password Standards
* **Concept:** Mandatory technical authentication specifications—minimum length (`14+ chars`), banned-password lists, MFA enforcement, lockout thresholds, and cryptographic storage (`Argon2id` / `PBKDF2`).
### 3. Physical Security Standards
* **Concept:** Mandatory facility protection specifications—badge access control tiers, CCTV retention periods (e.g., 90 days), server rack lock types, and environmental HVAC/fire-suppression thresholds.
### 4. RFCs (Requests for Comments)
* **Concept:** Formal technical specification documents published by the **IETF** (Internet Engineering Task Force) defining Internet protocols and cryptographic standards (e.g., `RFC 8446` for TLS 1.3, `RFC 3227` for Digital Evidence Order of Volatility, `RFC 9116` for `security.txt`).
### 5. Encryption Standards
* **Concept:** Mandatory cryptographic algorithm and key-length minimums—**AES-256** for data at rest, **TLS 1.2 / TLS 1.3** for data in transit, **SHA-256+** for integrity, and **RSA-2048 / Ed25519** for asymmetric signatures.

* **Practical Task (Enforce Technical Standards via Automated Compliance Check in Python):**
  ```python
  security_standard = {
      "min_password_length": 14,
      "allowed_tls_versions": {"TLSv1.2", "TLSv1.3"},
      "disk_encryption_algo": "AES-256"
  }

  server_audit = {"min_password_length": 10, "tls_version": "TLSv1.1", "disk_encryption_algo": "AES-256"}

  if server_audit["min_password_length"] < security_standard["min_password_length"]:
      print("[STANDARD VIOLATION] Password length below mandatory 14-character standard!")
  if server_audit["tls_version"] not in security_standard["allowed_tls_versions"]:
      print(f"[STANDARD VIOLATION] Deprecated protocol {server_audit['tls_version']} violates Encryption Standard!")
  ```

## Part C: Procedures & Plans (Operational Execution & Continuity)

### 1. Standard Operating Procedures (SOPs) vs. 2. Runbooks
* **Concept:**
  * **Standard Operating Procedures (SOPs):** Step-by-step, repeatable human instructions ensuring routine operational and security tasks (e.g., onboarding a new hire, rotating TLS certificates, imaging a laptop) are executed consistently without errors.
  * **Runbooks:** Detailed, tactical, **incident- or alert-specific** technical playbooks (often automated via SOAR) guiding responders step-by-step through diagnosing and resolving a specific failure or security alert (e.g., *"Runbook: High CPU / Suspected Cryptominer Containment"*).

### 3. Business Continuity Plans (BCP) vs. 4. Disaster Recovery Plans (DRP)
* **Concept:**
  * **Business Continuity Plan (BCP):** High-level organizational strategy ensuring critical business operations (staffing, payroll, customer support, supply chain, alternate workspaces) continue functioning during and after a major disruption.
  * **Disaster Recovery Plan (DRP):** Technical, IT-focused procedures and checklists to restore servers, networks, databases, and applications within **RTO/RPO** targets after an outage or cyberattack.

* **Practical Task (Create an Executable Incident Runbook Script `runbook_triage.sh`):**
  ```bash
  cat << 'EOF' > runbook_triage.sh
  #!/bin/bash
  echo "=== RUNBOOK: RAPID HOST TRIAGE ==="
  echo "[1] Active Network Listeners:" && ss -tuln | head -n 10
  echo "[2] Top 5 CPU Processes:"      && ps -eo pid,ppid,%cpu,%mem,comm --sort=-%cpu | head -n 6
  echo "[3] Recent Auth Failures:"     && sudo grep -i "failed" /var/log/auth.log 2>/dev/null | tail -n 5
  EOF

  chmod +x runbook_triage.sh
  ./runbook_triage.sh
  ```

## Part D: Organizational Security Policies (11 Mandatory Governance Policies)

> **Exam Tip:** CompTIA Security+ scenario questions frequently describe an employee behavior, device issue, or data handling problem and ask **which policy** governs it.

| Policy | What It Governs & Key Security+ Exam Triggers |
| :--- | :--- |
| **1. Bring Your Own Device (BYOD)** | Rules for personal smartphones/laptops accessing corporate data—mandates **MDM enrollment**, containerization, device encryption, passcode locks, and **remote wipe** rights upon loss or termination. |
| **2. Acceptable Use Policy (AUP)** | Defines permitted vs. prohibited use of company networks, computers, and internet (bans torrenting, crypto mining, unauthorized software, harassment); signed by all staff during onboarding. |
| **3. Clean Desk Policy** | Requires employees to lock screens (`Win+L`) when stepping away and clear sensitive physical documents, sticky-note passwords, and USB drives from desks at end of day. |
| **4. Information Security Policy** | Top-level overarching executive policy establishing the organization's security mission, governance structure, roles/responsibilities, and mandate for all subordinate policies. |
| **5. Incident Response Policy** | Authorizes the Incident Response Team (CSIRT) to isolate systems, collect forensic evidence, declare incidents, and defines escalation and mandatory external reporting duties. |
| **6. Data Classification Policy** | Defines sensitivity tiers (**Public, Internal, Confidential, Restricted**), labeling rules, and required protection levels for each tier. |
| **7. Data Retention Policy** | Specifies minimum and maximum storage timeframes for records (e.g., 7 years for financial/tax logs, 1 year for security logs) and **Litigation Hold** overrides. |
| **8. Access Control Policy** | Establishes **Least Privilege**, **Separation of Duties**, RBAC/MFA mandates, periodic access reviews, and immediate account deprovisioning rules. |
| **9. Data Disposal Policy** | Mandates approved media sanitization methods (**Crypto-shredding, Overwriting, Degaussing, Physical Destruction**) and **Certificates of Destruction** when retiring hardware/data. |
| **10. Vulnerability Disclosure Policy** | Defines how external security researchers can safely report discovered flaws (`security.txt`), sets remediation timelines, and provides **Safe Harbor** legal protection. |
| **11. Privacy Policy** | Public-facing and internal commitment detailing how PII/customer data is collected, used, shared, protected, and how users exercise data rights (GDPR/CCPA). |

* **Practical Task (Build a Policy-as-Code Compliance Validator in Python):**
  ```python
  # Validate employee & system events against organizational Policies
  events = [
      {"policy": "BYOD",           "mdm_enrolled": False, "device_encrypted": True},
      {"policy": "Data_Retention", "record_age_yrs": 8,   "max_retention_yrs": 7, "litigation_hold": False},
      {"policy": "Access_Control", "privileged_role": True, "mfa_enabled": False}
  ]

  for e in events:
      if e["policy"] == "BYOD" and not e["mdm_enrolled"]:
          print("[BYOD POLICY VIOLATION] Unenrolled personal device blocked from corporate email!")
      elif e["policy"] == "Data_Retention" and e["record_age_yrs"] > e["max_retention_yrs"] and not e["litigation_hold"]:
          print("[DATA RETENTION / DISPOSAL POLICY] Expired record flagged for secure sanitization!")
      elif e["policy"] == "Access_Control" and e["privileged_role"] and not e["mfa_enabled"]:
          print("[ACCESS CONTROL POLICY VIOLATION] Privileged account missing mandatory MFA!")
  ```
