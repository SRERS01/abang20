## Part A: Training Types (4 Approaches)

| Training Type | When It Is Triggered & Core Purpose |
| :--- | :--- |
| **1. Initial Onboarding** | Delivered to all new hires, contractors, and interns **before** granting access to production systems—covers Acceptable Use Policy (AUP), password/MFA setup, phishing recognition, and data handling basics. |
| **2. Ongoing Training** | Recurring enterprise-wide refresher sessions (annual, quarterly, or monthly micro-learning modules) keeping security top-of-mind and updating staff on new corporate policies. |
| **3. Targeted Training** | Role-specific curriculum tailored to high-risk job functions—e.g., **Secure Coding (OWASP)** for developers, **BEC / Wire Verification** for Finance/Accounts, **Whaling / Deepfake** awareness for Executives, and **HIPAA/PCI** handling for frontline staff. |
| **4. Corrective Training** | Just-in-time remedial coaching automatically assigned to an individual immediately *after* a policy violation or failed behavioral test (e.g., clicking a simulated phishing link, plugging in an unapproved USB drive, or leaving a workstation unlocked). |

---

## Part B: Training Delivery Mechanisms (4 Channels)

### 1. Learning Management Systems (LMS)
* **Concept:** Centralized enterprise training platforms (e.g., KnowBe4, Moodle, Proofpoint, Workday Learning) that host interactive video modules, track completion percentages, administer quizzes, and log mandatory compliance attestations for auditors.

### 2. Self-Service Portals
* **Concept:** On-demand internal knowledge bases, intranet security hubs, and FAQ portals where employees can independently look up security SOPs, download approved password managers, check phishing reporting instructions, or request access reviews anytime.

### 3. One-to-One Training
* **Concept:** Personalized, direct coaching between a security specialist and a single individual—used for **executive/VIP white-glove onboarding**, high-privilege administrator briefings, or sensitive **corrective training** after a repeated security mistake.

### 4. One-to-Many Training
* **Concept:** Scalable group sessions delivering unified awareness to broad audiences simultaneously—live town halls, webinars, lunch-and-learns, security newsletters, and department workshops.

## Part C: Measuring Effectiveness & Human Risk Scoring (3 Metrics)

### 1. Security Awareness Metrics, 2. Management Reports & 3. Personnel Behavior Risk Scoring
* **Concept:**
  * **Security Awareness Metrics:** Quantitative KPIs measuring program impact over time—**Training Completion Rate (%)**, **Phishing Simulation Click Rate (%)**, **Phishing Report Rate (%)** ("Report Phish" button usage), **Time-to-Report**, and **Repeat Offender Rate**.
  * **Management Reports:** Executive dashboards and quarterly board summaries linking awareness metrics to tangible risk reduction (e.g., *"Phishing click rate dropped from 18% to 3.2% following targeted BEC drills"*).
  * **Personnel Behavior Risk Scoring:** Assigning dynamic, weighted risk scores to individual users based on real behavioral telemetry (phishing clicks, malware blocks, DLP policy triggers, bypassed MFA prompts, role privilege level) to automatically assign **targeted or corrective training**.

* **Practical Task (Build a Personnel Behavior Risk Scoring & Corrective Training Trigger Engine in Python):**
  ```python
  import json

  personnel_telemetry = [
      {"user": "ambe.fon",   "dept": "Finance", "phish_clicks": 0, "phish_reported": 4, "dlp_alerts": 0, "is_privileged": True},
      {"user": "john.doe",   "dept": "Sales",   "phish_clicks": 2, "phish_reported": 0, "dlp_alerts": 1, "is_privileged": False},
      {"user": "grace.ngwa", "dept": "IT_Ops",  "phish_clicks": 1, "phish_reported": 2, "dlp_alerts": 0, "is_privileged": True}
  ]

  print("=== PERSONNEL BEHAVIOR RISK SCORE & TRAINING ENGINE ===")
  for p in personnel_telemetry:
      # Calculate weighted risk score (0-100 scale)
      score = (p["phish_clicks"] * 25) + (p["dlp_alerts"] * 20) + (15 if p["is_privileged"] else 0) - (p["phish_reported"] * 5)
      score = max(0, min(100, score))

      if score >= 50:
          action = "ASSIGN: Corrective Training + One-to-One Coaching"
      elif p["dept"] == "Finance" or p["is_privileged"]:
          action = "ASSIGN: Targeted Role-Specific Training (BEC / Privileged Hygiene)"
      else:
          action = "STANDARD: Ongoing Quarterly Refresher"

      print(f"User: {p['user']:<12} | Dept: {p['dept']:<8} | Risk Score: {score:>3}/100 | Action: {action}")
  ```

## Part D: Common Security Awareness Training Topics (12 Core Areas)

| Training Topic | Key Behavioral Habits Taught to Employees |
| :--- | :--- |
| **1. Social Engineering** | Recognizing psychological manipulation triggers (urgency, fear, authority, scarcity) across email, phone, SMS, and in-person interactions. |
| **2. Emerging Security Threats** | Staying alert to evolving attack trends—AI deepfake voice/video calls, QR code phishing (**quishing**), MFA push fatigue, and fake CAPTCHA malware lures. |
| **3. Password Management** | Creating unique 14–16+ character passphrases, using corporate **password managers**, and never reusing work passwords on personal websites. |
| **4. Credential Management** | Protecting API keys, SSH keys, smartcards, and MFA tokens—never sharing passwords with coworkers/IT, never approving unexpected MFA prompts, and reporting lost tokens immediately. |
| **5. Remote Working** | Securing home Wi-Fi routers (WPA2/WPA3, strong admin password), using corporate **VPNs**, locking screens around family/roommates, and prohibiting work on shared personal PCs. |
| **6. Hybrid Working** | Safely transitioning between home and office—never leaving laptops unattended in vehicles/cafés, using privacy screen filters on public transit, and verifying physical network connections. |
| **7. BYOD (Bring Your Own Device)** | Enrolling personal smartphones/tablets in **MDM**, keeping mobile OS updated, avoiding jailbreaking/rooting, and respecting corporate containerization/remote-wipe policies. |
| **8. Business Email Compromise (BEC)** | Detecting spoofed executive/vendor emails requesting urgent wire transfers or gift cards; enforcing **out-of-band phone callback verification** using known directory numbers before releasing funds. |
| **9. Removable Media** | Never plugging found or untrusted USB flash drives into corporate computers (**BadUSB** risk); using only IT-approved, hardware-encrypted USB drives when authorized. |
| **10. Security Cables** | Using physical steel cable locks (Kensington locks) to tether laptops and docking stations to desks in open offices, libraries, hotels, and conference booths to prevent grab-and-run theft. |
| **11. Situational Awareness** | Maintaining active vigilance in physical surroundings—spotting **tailgating** at badge doors, **shoulder surfing** at ATMs/cafés, unescorted visitors without badges, and suspicious hardware overlays. |
| **12. Operational Security (OPSEC)** | Avoiding oversharing sensitive workplace details on public social media (e.g., posting photos of employee ID badges, whiteboards, server racks, or internal software tools that aid attacker OSINT). |

* **Practical Task (Build a Phishing Simulation & SOC Reporting Campaign Dashboard in Python):**
  ```python
  campaign_stats = {
      "campaign_name": "Q4-2026-Fake-Invoice-Sim",
      "total_emails_sent": 250,
      "emails_opened": 110,
      "links_clicked": 12,
      "credentials_submitted": 3,
      "reported_to_soc": 84
  }

  click_rate = (campaign_stats["links_clicked"] / campaign_stats["total_emails_sent"]) * 100
  report_rate = (campaign_stats["reported_to_soc"] / campaign_stats["total_emails_sent"]) * 100
  resilience_ratio = campaign_stats["reported_to_soc"] / max(1, campaign_stats["links_clicked"])

  print(f"=== MANAGEMENT REPORT: {campaign_stats['campaign_name']} ===")
  print(f"  Phishing Click Rate      : {click_rate:.1f}% ({campaign_stats['links_clicked']}/{campaign_stats['total_emails_sent']})")
  print(f"  Credential Compromise    : {campaign_stats['credentials_submitted']} users (Triggered immediate Corrective Training)")
  print(f"  SOC Phish Report Rate    : {report_rate:.1f}% ({campaign_stats['reported_to_soc']} reports)")
  print(f"  Report-to-Click Ratio    : {resilience_ratio:.1f}:1 (Higher is better)")
  ```
