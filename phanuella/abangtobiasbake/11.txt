### Complete mobile application security testing toolkit

You can use your Ubuntu laptop and Android emulator to discover and validate a wide range of mobile application vulnerabilities without Burp Suite.

I will organize this into three parts:

* The vulnerabilities you can discover and safely validate.

* Every tool, how to start it, and what job it performs.

* A practical testing sequence showing which tool to use for each vulnerability.

This is for applications you own, intentionally vulnerable training applications, or applications you have explicit permission to test. For potentially dangerous findings such as RCE and SSRF, use an isolated lab and harmless proof-of-execution or callback tests.

### Part 1 — Vulnerabilities you can discover

### A. API and authorization vulnerabilities

| Vulnerability                   | What you are looking for                               |
| ------------------------------- | ------------------------------------------------------ |
| IDOR / BOLA                     | Accessing another user's object                        |
| BFLA                            | Performing functions outside your permission           |
| Broken access control           | Unauthorized access to protected resources             |
| Mass assignment                 | Modifying protected fields through API input           |
| Broken authentication           | Weaknesses in login and identity verification          |
| Broken session management       | Incorrect session creation, expiration or invalidation |
| Token leakage                   | Access tokens exposed in responses, logs or storage    |
| JWT weaknesses                  | Incorrect token validation or authorization claims     |
| Password reset flaws            | Weaknesses in recovery and verification                |
| Account enumeration             | Revealing whether an account exists                    |
| Missing rate limiting           | Insufficient controls on sensitive requests            |
| Replay attacks                  | Reusing requests or tokens improperly                  |
| Privilege escalation            | Obtaining unauthorized permissions                     |
| Excessive data exposure         | Returning unnecessary private information              |
| Insecure direct function access | Calling restricted API functions directly              |

### B. Injection vulnerabilities

| Vulnerability                         | What you are looking for                             |
| ------------------------------------- | ---------------------------------------------------- |
| SQL injection                         | Unsafe database query construction                   |
| NoSQL injection                       | Unsafe document-database queries                     |
| Command injection                     | Untrusted input reaching operating-system commands   |
| LDAP injection                        | Unsafe LDAP query construction                       |
| XML injection                         | Unsafe XML processing                                |
| XPath injection                       | Unsafe XPath query construction                      |
| Server-side template injection (SSTI) | Untrusted template expressions being evaluated       |
| Cross-site scripting (XSS)            | Untrusted content executing in a web context         |
| Header injection                      | Untrusted input modifying HTTP headers               |
| CRLF injection                        | Improper handling of carriage returns and line feeds |
| JSON injection                        | Unsafe construction or processing of JSON            |
| GraphQL injection                     | Unsafe query or resolver behavior                    |

### C. Server-side vulnerabilities

| Vulnerability            | What you are looking for                          |
| ------------------------ | ------------------------------------------------- |
| SSRF                     | Server making unauthorized network requests       |
| RCE                      | Unintended remote code execution                  |
| Arbitrary file read      | Accessing files outside permitted boundaries      |
| Arbitrary file write     | Writing files without proper authorization        |
| Path traversal           | Escaping intended directory boundaries            |
| Insecure deserialization | Unsafe processing of serialized objects           |
| XXE                      | XML external entity processing                    |
| Unsafe file upload       | Dangerous or improperly validated uploads         |
| Open redirect            | Unrestricted redirection to external destinations |
| Request smuggling        | Inconsistent HTTP request parsing                 |
| Cache poisoning          | Manipulating shared cached responses              |
| Cache deception          | Exposing private content through caching          |
| Information disclosure   | Exposing internal system information              |
| Debug endpoint exposure  | Unprotected development or diagnostic interfaces  |

### D. Android-specific vulnerabilities

| Vulnerability                     | What you are looking for                                 |
| --------------------------------- | -------------------------------------------------------- |
| Insecure local storage            | Sensitive data stored without adequate protection        |
| Hardcoded secrets                 | API keys, credentials or tokens in application code      |
| Insecure SharedPreferences        | Sensitive preferences stored insecurely                  |
| Insecure SQLite database          | Sensitive information stored without adequate protection |
| Exported activities               | Activities accessible to unauthorized applications       |
| Exported services                 | Services exposed without suitable authorization          |
| Exported broadcast receivers      | Unintended external broadcast interaction                |
| Insecure content providers        | Unauthorized data access                                 |
| Deep-link vulnerabilities         | Unsafe handling of incoming links                        |
| Intent vulnerabilities            | Untrusted intent data being processed                    |
| WebView vulnerabilities           | Unsafe JavaScript, URL or content handling               |
| Certificate validation flaws      | Improper server certificate verification                 |
| Certificate pinning weaknesses    | Incorrect or ineffective pinning implementation          |
| Cleartext traffic                 | Sensitive communications sent without TLS                |
| Backup exposure                   | Sensitive information included in backups                |
| Clipboard leakage                 | Sensitive data exposed through clipboard operations      |
| Screenshot leakage                | Sensitive screens captured unexpectedly                  |
| Log leakage                       | Secrets or personal information written to logs          |
| Insecure biometric implementation | Incorrect biometric authentication design                |
| Weak cryptography                 | Inadequate algorithms or key management                  |
| Dynamic code loading risks        | Unsafe loading of executable code                        |

### E. Business logic and financial vulnerabilities

These are particularly important because an application can have strong encryption and still contain serious business logic errors.

* Negative balance or invalid balance transitions.

* Duplicate payments.

* Duplicate withdrawals.

* Unauthorized refunds.

* Incorrect transaction ownership.

* Incorrect transaction amount validation.

* Currency conversion errors.

* Decimal precision errors.

* Integer overflow and underflow.

* Race conditions.

* Time-of-check/time-of-use (TOCTOU) errors.

* Incorrect transaction state transitions.

* Missing transaction limits.

* Unauthorized changes to account details.

* Incorrect discount or promotion calculations.

* Subscription entitlement errors.

* Inconsistent inventory or order quantities.

* Payment verification failures.

### F. Network and infrastructure vulnerabilities

* Weak TLS configuration.

* Unnecessary open ports.

* DNS misconfiguration.

* Insecure HTTP endpoints.

* Missing security headers.

* Insecure CORS configuration.

* Exposed development services.

* Unprotected administrative endpoints.

* Weak API gateway controls.

* Inadequate logging and monitoring.

* Misconfigured cloud storage.

* Excessive API permissions.

### Part 2 — Tools, their jobs, and how to start them

You do not need every tool running simultaneously. Start the tools according to the type of test you are performing.

### 1\. Prepare your Ubuntu environment

Install the common dependencies:

```bash
sudo apt update

sudo apt install -y \
  adb \
  fastboot \
  tcpdump \
  wireshark \
  sqlite3 \
  curl \
  git \
  python3 \
  python3-venv \
  python3-pip \
  openjdk-17-jdk \
  docker.io \
  nodejs \
  npm
```

Create a working directory and Python environment:

```bash
mkdir -p ~/mobile-security-lab
cd ~/mobile-security-lab

python3 -m venv venv
source venv/bin/activate

pip install --upgrade pip
pip install requests httpx mitmproxy frida-tools objection
```

Check that the main tools are available:

```bash
adb version
java -version
python3 --version
docker --version
mitmproxy --version
frida --version
```

### Connect your Android emulator to mitmproxy

For the standard Android Studio emulator, the host computer is reachable at `10.0.2.2`.

First, check your emulator:

```bash
adb devices
```

Set its proxy:

```bash
adb shell settings put global http_proxy 10.0.2.2:8081
```

Verify:

```bash
adb shell settings get global http_proxy
```

To remove the proxy afterward:

```bash
adb shell settings put global http_proxy :0
```

For HTTPS inspection, install the mitmproxy CA certificate in your test emulator. Remember that some apps do not trust user-installed certificates or use certificate pinning.

### Part 3 — Recommended order for a complete assessment

Follow this sequence instead of launching everything at once.

### Mobile application penetration-testing workflow

* Prepare the emulator

    Tools: Android Studio Emulator, ADB.

    ```bash
    adb devices -l
    adb install -r target.apk
    adb logcat -c
    ```

* Analyze the APK

    Tools: MobSF, JADX, APKTool.

    ```bash
    jadx -d decoded_app target.apk
    apktool d target.apk -o apk_decoded
    ```

    Look for API endpoints, exported components, hardcoded secrets, WebViews and unsafe code patterns.

* Capture network traffic

    Tools: mitmproxy, PCAPdroid, Wireshark.

    ```bash
    mitmweb --listen-port 8081
    ```

    Interact with the application and record its requests.

* Test API security

    Tools: Postman, curl, Python.

    Examine authorization, authentication, IDOR, mass assignment, rate limiting and input validation using accounts you control.

* Test application runtime behavior

    Tools: Frida, Objection, ADB, Appium.

    Inspect runtime behavior, local storage, deep links, application components and session handling.

* Investigate server-side vulnerabilities

    Tools: ZAP, Postman, mitmproxy.

    Use isolated test endpoints to assess SSRF, injection, file handling and other server-side weaknesses.

* Document and verify findings

    Tools: Wireshark, SQLite3, MobSF and your test logs.

    Record reproducible evidence, impact, affected endpoint and remediation.

* Authentication and authorization.

* Business logic vulnerabilities.

* SQL injection and input validation.

* SSRF and file upload security.

* Android local storage and exported components.

* Runtime analysis with Frida.

* Race conditions and transaction integrity.

Use intentionally vulnerable applications such as [DIVA Android](https://github.com/payatu/diva-android?utm_source=chatgpt.com) to practise Android-specific security testing.

For structured learning, use the [OWASP Mobile Application Security Testing Guide](https://mas.owasp.org/MASTG/?utm_source=chatgpt.com).

One important point: You cannot discover every possible vulnerability with a fixed list of tools. Some require source-code review, some require backend access, and others require carefully designed runtime experiments.

My recommendation is to master mitmproxy, JADX, MobSF, Frida and Postman first. Together, they give you a strong foundation for Android application security testing without Burp Suite.
