In a real bug bounty, an offensive security researcher would test whether the authentication system detects one password being attempted against multiple accounts, rather than simply checking whether one account gets locked.

I can give you a realistic Python assessment script with a fictional endpoint and fake usernames. It will simulate the spraying pattern without sending credential-guessing attempts to real accounts.

### 1\. Assumed bug bounty endpoint

Imagine the authorized program provides this API:

```http
POST https://api.example.com/v1/auth/login
Content-Type: application/json
```

Request format:

```json
{
  "username": "researcher-test-01",
  "password": "YOUR_APPROVED_TEST_PASSWORD"
}
```

Fictional test accounts:

```python
TEST_USERS = [
    "researcher-test-01",
    "researcher-test-02",
    "researcher-test-03",
    "researcher-test-04"
]
```

Use only accounts explicitly supplied or approved by the bug bounty program.

### 2\. Python script: controlled spraying-pattern assessment

This version:

* Uses one candidate password across multiple approved test accounts.

* Sends only one attempt per account.

* Requires an explicit list of approved test accounts.

* Stops on success, rate limiting or unexpected responses.

* Records response codes and timing.

* Does not rotate IP addresses, evade protections or expand the account list.

```python

import requests
import time
import csv
from datetime import datetime, timezone

# Fictional example: replace only with a program-approved
# authentication endpoint and approved test accounts.

LOGIN_URL = "https://api.example.com/v1/auth/login"

APPROVED_TEST_USERS = [
    "researcher-test-01",
    "researcher-test-02",
    "researcher-test-03",
    "researcher-test-04",
]

CANDIDATE_PASSWORD = "YOUR_APPROVED_TEST_PASSWORD"

DELAY_SECONDS = 10
TIMEOUT = 10

# Explicit authorization confirmation
AUTHORIZED = False

def main():

    if not AUTHORIZED:
        raise SystemExit(
            "Set AUTHORIZED=True only after confirming "
            "the bug bounty rules permit this test."
        )

    if "api.example.com" in LOGIN_URL:
        raise SystemExit("Replace the fictional endpoint.")

    session = requests.Session()

    results = []

    for number, username in enumerate(
        APPROVED_TEST_USERS, start=1
    ):

        print(f"\nTesting approved account {number}")
        print("Username:", username)

        start = time.monotonic()

        try:
            response = session.post(
                LOGIN_URL,
                json={
                    "username": username,
                    "password": CANDIDATE_PASSWORD
                },
                headers={
                    "Content-Type": "application/json",
                    "User-Agent": "Authorized-Bug-Bounty-Assessment"
                },
                timeout=TIMEOUT,
                allow_redirects=False
            )

            elapsed = round(
                time.monotonic() - start, 3
            )

            result = {
                "timestamp": datetime.now(
                    timezone.utc
                ).isoformat(),
                "username": username,
                "status": response.status_code,
                "elapsed_seconds": elapsed,
                "retry_after": response.headers.get(
                    "Retry-After", ""
                )
            }

            results.append(result)

            print("HTTP:", response.status_code)
            print("Response time:", elapsed, "seconds")
            print("Retry-After:", result["retry_after"])

            if response.status_code == 429:
                print("Rate limit encountered. Stopping.")
                break

            if response.status_code in (200, 201):
                print("Authentication may have succeeded.")
                print("Stopping immediately.")
                break

            if response.status_code >= 500:
                print("Server error. Stopping.")
                break

        except requests.RequestException as error:
            print("Request failed:", error)
            break

        if number < len(APPROVED_TEST_USERS):
            time.sleep(DELAY_SECONDS)

    with open(
        "spray_assessment.csv",
        "w",
        newline=""
    ) as file:

        writer = csv.DictWriter(
            file,
            fieldnames=[
                "timestamp",
                "username",
                "status",
                "elapsed_seconds",
                "retry_after"
            ]
        )

        writer.writeheader()
        writer.writerows(results)

    print("\nAssessment finished.")
    print("Results saved to spray_assessment.csv")

if __name__ == "__main__":
    main()
```

This is a bounded test of the spraying pattern, not an automated password-guessing campaign.

### 3\. What to investigate in the responses

| Observation                                      | Interpretation                                    |
| ------------------------------------------------ | ------------------------------------------------- |
| 401                                              | Authentication rejected                           |
| 403                                              | Request forbidden; investigate policy             |
| 429                                              | Rate limiting encountered                         |
| 423                                              | Account may be locked                             |
| 200                                              | Inspect whether authentication actually succeeded |
| 500                                              | Server error; investigate logs                    |
| Different errors for valid and invalid usernames | Possible account enumeration                      |

A `401` for every account does not prove that password spraying is prevented.

### 4\. What makes a valid bug bounty finding?

Look for evidence that the server fails to detect suspicious authentication activity across accounts.

A useful report should establish:

* The endpoint and permitted testing scope.

* The test accounts you were authorized to use.

* The controlled request sequence.

* The server's rate-limit and monitoring behavior.

* The security impact.

* A reproducible remediation recommendation.

Do not claim a vulnerability merely because the endpoint accepts several failed logins. Some programs explicitly prohibit automated authentication testing.

### 5\. Important bug bounty distinction

There are three different controls worth evaluating:

* Per-account throttling: Limits attempts against an individual account.

* Per-source throttling: Limits attempts from one IP address or device.

* Cross-account detection: Identifies suspicious failures spread across several accounts.

The third is particularly relevant to password spraying.

One important question: Does the bug bounty program provide you with multiple approved test accounts, or only one researcher account? That determines which testing method is appropriate.
