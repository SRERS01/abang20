However, the following is a comprehensive classification of evasion techniques used in network security, web application penetration testing, Android security, API testing, malware analysis and infrastructure security.

I'll distinguish the technique, what it attempts to evade, and what a security researcher should examine in an authorized lab.

### 11\. Evasion testing methodology

Knowing the names is only the beginning. A security researcher needs to understand how to evaluate the control.

A typical defensive-control assessment

* Identify the control

    Example: API rate limiter.

* Identify its security assumption

    Example: Requests from one account should be limited.

* Identify different input representations

    Example: Case differences, encoding, JSON types and missing values.

* Test in an authorized environment

    Use controlled accounts, test data and bounded requests.

* Observe the outcome

    Check HTTP responses, application logs, alerts and server-side decisions.

* Document the weakness

    Explain the control, expected behavior, actual behavior and remediation.

### 12\. The most important concepts to master

I recommend learning these underlying concepts because they explain many different evasion vulnerabilities:

* Parsing differences – two components interpret the same input differently.

* Encoding differences – security filters and applications decode data differently.

* Normalization differences – equivalent representations are treated inconsistently.

* State inconsistencies – security checks fail when application state changes.

* Trust-boundary weaknesses – one component trusts data that another component has not validated.

* Distributed detection weaknesses – monitoring fails to correlate activity across accounts, devices or sources.

* Timing and concurrency weaknesses – security decisions behave differently under simultaneous operations.

* Incomplete enforcement – one endpoint or execution path lacks the required security check.

* Context confusion – data is interpreted differently depending on where it is used.

* Observability gaps – suspicious activity occurs without adequate logging or alerting.

My recommendation: Master parsing, encoding, normalization, state management and trust boundaries first. These concepts appear repeatedly in WAF, API, Android, authentication and network-security assessments.
