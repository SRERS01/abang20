In the context of Remote Code Execution (RCE) or Command Injection within local laboratory testing (such as DVWA, bWAPP, or custom backend templates), web application vulnerabilities are assessed using Bash/Linux shell execution operators rather than SQL syntax.
Command injection occurs when user inputs are directly passed into OS system execution wrappers like Node's child_process.exec(), Python's os.system(), or PHP's system()/exec() functions. [1] 
To manipulate shell commands and ensure your payload evaluates as True (meaning it executes your secondary command alongside or instead of the original server logic), security analysts leverage specific OS command sequencing symbols.
------------------------------
## 1. The Full Shell Logical Operators (Linux/Unix Command Matrix)
These structural operators dictate how sequential shell tasks handle system outcomes.

* The Sequential Execution Operator ( ; )
* How it works: Executes the trailing command regardless of whether the preceding command succeeds or crashes. This is the most reliable way to force execution.
   * Lab Vector: ?ip=127.0.0.1; whoami
* The Logical AND Operator ( && )
* How it works: Executes the trailing command only if the preceding command finishes successfully with an exit status of 0.
   * Lab Vector: ?ip=127.0.0.1 && whoami (URL-encoded as %26%26)
* The Logical OR Operator ( || )
* How it works: Executes the trailing command only if the preceding command fails with an error (non-zero exit code).
   * Use Case: Excellent when you need to bypass or break the default command the developer intended to run. If you pass an invalid argument (like an IP address that doesn't exist), the system errors out and forces the execution of your payload.
   * Lab Vector: ?ip=broken_argument || whoami (URL-encoded as %7C%7C)
* The Newline / Carriage Return Operator ( %0a / %0d )
* How it works: Simulates hitting the "Enter" key on a terminal keyboard. This isolates your input onto a fresh command stream buffer, completely neutralizing the rest of the developer's original string wrapper.
   * Lab Vector: ?ip=127.0.0.1%0awhoami

------------------------------
## 2. Stream Interception Operators (Piping and Redirection)
These tools manipulate where data goes or force the output of one program to feed right into another command.

* The Standard Pipe Operator ( | )
* How it works: Takes the standard output stream of the left-hand command and passes it directly as the input text block for the right-hand command.
   * Lab Vector: ?ip=127.0.0.1 | whoami (URL-encoded as %7C)
* The Output Redirection Operator ( > / >> )
* How it works: Overwrites (>) or appends (>>) the output log of your system commands straight into a local server file. This is commonly used in laboratories to drop web shells into public directories.
   * Lab Vector: ?ip=127.0.0.1; id > output.txt

------------------------------
## 3. Inline Evaluation Context Operators
If an input variable is enclosed tightly inside pre-existing quotes or syntax filters, you can use evaluation strings to execute background terminal processing before the system completes its main loop.

* The Backtick Execution Context ( ` )
* How it works: The shell intercepts the text inside the backticks, processes it as a command, and replaces the string block with the output text natively.
   * Lab Vector: ?ip=127.0.0.1; echo \whoami``
* The Inline Shell Variable Wrapper ( $() )
* How it works: Functions identically to backticks, but is safer against nesting constraints within complex backend terminal languages.
   * Lab Vector: ?ip=127.0.0.1; echo $(whoami)
